# IMPLEMENTATION: 방 비밀번호 평문 저장 전환

## Background / Context

room 도메인 하단에서는 비밀방 비밀번호를 SHA-256으로 해싱해 비교하는 전제가 일부 코드와 설명에 남아 있었다.
하지만 현재 정책은 방 비밀번호를 별도 해시/암호화 없이 Redis에 평문으로 저장하고, 검증 시에도 평문 비교를 사용하는 것이다.

이 불일치가 남아 있으면 실제 저장값과 검증 로직이 어긋나 비밀번호 검증 실패를 유발할 수 있고,
후속 작업자가 room 비밀번호 저장 방식을 잘못 이해할 가능성도 생긴다.

## Decision

room 비밀번호 검증 로직에서 SHA-256 해시 계산을 제거하고, Redis `password` 필드와 요청값을 평문으로 직접 비교하도록 정리했다.
관련 테스트와 API 문서도 동일한 정책을 기준으로 수정했다.

배제한 대안:
- SHA-256 저장 정책 유지: 현재 저장 정책과 맞지 않아 검증 불일치가 발생함
- 문서만 수정: 런타임 동작과 테스트가 계속 해시 전제를 유지하므로 문제를 해결하지 못함

## Why

현재 room 비밀번호는 인증 계정 비밀번호와 달리 임시 방 접근 제어 용도이며,
실제 저장 매체도 Redis 실시간 방 정보 Hash다.
따라서 우선순위는 보안 정책 확장보다 구현 정책 일치와 런타임 정합성 확보에 있다.

## Caution

- 이 문서는 "현재 정책" 기준이다. 추후 해시 저장으로 되돌릴 경우 생성, 수정, 검증, 입장 플로우와 문서를 함께 변경해야 한다.
- 평문 저장 정책이어도 로그에는 비밀번호 원문을 남기면 안 된다.
- 비밀번호 검증 성공 후 저장하는 `room:{roomId}:password:verified:{memberId}` TTL 키 동작은 그대로 유지한다.

## Test Plan

- 비밀방 password가 Redis에 평문으로 저장된 상태에서 동일한 요청값으로 검증 성공 확인
- 다른 문자열 입력 시 `INVALID_PASSWORD` 반환 확인
- 존재하지 않는 방에 대해 `ROOM_NOT_FOUND` 반환 확인
