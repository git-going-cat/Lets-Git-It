# 청킹 전략

### Background / Context

Pro Git 전체 텍스트를 그대로 Pinecone에 저장할 수 없어 토큰 단위로 잘라야 한다. 청크가 너무 작으면 맥락이 부족해 답변 품질이 떨어지고, 너무 크면 임베딩 정밀도가 낮아진다. 또한 AsciiDoc 파싱 결과 섹션 크기가 수십~수천 토큰으로 불균일하다.

### Decision

**tiktoken `cl100k_base` + 섹션 누적 방식** (목표 500~800 토큰/청크, 오버랩 80 토큰)

| 파라미터 | 값 |
|---|---|
| 목표 토큰 (`CHUNK_TARGET`) | 650 |
| 최대 토큰 (`CHUNK_MAX`) | 800 |
| 오버랩 (`OVERLAP`) | 80 |
| 최소 토큰 (`MIN_CHUNK_TOKENS`) | 50 |

청킹 알고리즘:
1. **섹션 누적**: 작은 섹션들을 `CHUNK_MAX`에 도달할 때까지 하나의 청크로 합산
2. **챕터 경계 강제 flush**: 챕터(`==` 레벨) 변경 시 반드시 새 청크 시작
3. **대형 섹션 분할**: `CHUNK_MAX` 초과 시 오버랩 슬라이딩 윈도우로 분할
4. **최소 길이 필터**: 50 토큰 미만 청크 제거

### Why

| 옵션 | 장점 | 단점 |
|---|---|---|
| **섹션 누적 방식** | 챕터 맥락 보존, 균일한 크기 | 구현 복잡도 약간 높음 |
| 섹션별 개별 청크 | 구현 단순 | 짧은 섹션 수백 개 → tiny chunk 양산 |
| 고정 토큰 슬라이딩 윈도우 | 크기 균일 | 문장/섹션 경계 무시, 맥락 단절 |

섹션별 개별 청크로 구현 시 1550개, avg 323 토큰으로 tiny chunk가 547개(35%) 발생했다. 섹션 누적 방식으로 전환 후 589개, avg 559 토큰으로 개선됨.

오버랩은 대형 섹션을 분할할 때만 적용된다. 청크 경계에서 문장이 잘렸을 때 앞 청크의 마지막 80 토큰을 다음 청크에 반복해 맥락 단절을 방지한다.

### Caution

- tiktoken `cl100k_base`는 OpenAI 모델 계열 토크나이저 — `text-embedding-3-small` 및 `gpt-4o-mini`와 토큰 수 일치
- 임베딩 모델 변경 시 토크나이저도 함께 검토 필요
- `CHUNK_TARGET`을 높이면 청크당 맥락은 넓어지지만 임베딩 정밀도 저하 가능

### Test Plan

- `scripts/ingest.py --chunk` 실행 후 통계 확인: avg 500~650, max ≤ 800
- 전체 청크 수: Pro Git 한국어판 기준 500~650개 예상
- 청크 내 챕터 경계 혼입 없는지 확인 (metadata.chapter와 본문 일치)
