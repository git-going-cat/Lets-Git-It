# AsciiDoc 파서 구현

### Background / Context

`progit/progit2-ko` 저장소는 `.asc` (AsciiDoc) 포맷으로 작성되어 있다. RAG 청킹을 위해 파일을 텍스트로 변환할 방법이 필요했다. 외부 라이브러리 없이 헤더 구조와 본문 텍스트를 추출하는 파서가 요구된다.

### Decision

**정규식 기반 직접 파서** 사용 (외부 AsciiDoc 라이브러리 미사용)

### Why

RAG 시스템에서 필요한 정보는 **헤더 구조(챕터/섹션명)** 와 **본문 텍스트** 뿐이다. Pro Git 원본은 비교적 단순한 AsciiDoc을 사용하고 있어서 전체 스펙 지원이 불필요하다.

| 옵션 | 장점 | 단점 |
|---|---|---|
| **정규식 직접 파서** | 의존성 없음, 가볍고 디버깅 쉬움 | 복잡한 AsciiDoc 문법 일부 미지원 |
| `asciidoc` / `asciidoctor` (Python) | 완전한 파싱 | 의존성 많음, Java 런타임 필요(asciidoctor-j) |
| AsciiDoc → HTML → 텍스트 변환 체인 | 범용 | 코드블록 깨짐, 메타데이터 손실 위험 |

정규식으로 처리할 패턴:
- 헤더: `== 제목`, `=== 소제목` (레벨별 분기)
- `include::...[]` 디렉티브: 파일 경로 추출 후 재귀 처리
- `[source,console]` + `----` 블록: 코드블록 보존
- `NOTE:`, `TIP:`, `WARNING:` 사이드바: 본문으로 포함

### Caution

- 복잡한 AsciiDoc 문법(중첩 include, 조건부 블록 등) 미지원
- Pro Git 원본 외 다른 AsciiDoc 문서에는 재사용 불가
- **progit2-ko 전용 패턴**: 번역팀이 `//////////`(슬래시 10개)를 영어 원문 주석 블록 구분자로 사용. 표준 AsciiDoc 주석(`////`)과 다르므로 별도 처리 필요. 이를 필터링하지 않으면 영어 원문이 한국어 청크에 섞여 들어가 RAG 품질이 저하됨.

### Test Plan

- `scripts/ingest.py --chunk` 실행 후 `data/chunks.json` 수동 검수
- 챕터/섹션 제목이 메타데이터에 올바르게 포함되는지 확인
- 코드블록이 원본 그대로 보존되는지 확인
- 청크 내 영어 원문 혼입 여부 확인 (`//////////` 필터 검증)
