git-stash(1)
============

NAME
----
git-stash - Stash the changes in a dirty working directory away

SYNOPSIS
--------
[synopsis]
git stash list [<log-options>]
git stash show [-u | --include-untracked | --only-untracked] [<diff-options>] [<stash>]
git stash drop [-q | --quiet] [<stash>]
git stash pop [--index] [-q | --quiet] [<stash>]
git stash apply [--index] [-q | --quiet] [--label-ours=<label>] [--label-theirs=<label>] [--label-base=<label>] [<stash>]
git stash branch <branchname> [<stash>]
git stash [push] [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-q | --quiet]
	     [-u | --include-untracked] [-a | --all] [(-m | --message) <message>]
	     [--pathspec-from-file=<file> [--pathspec-file-nul]]
	     [--] [<pathspec>...]
git stash save [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-q | --quiet]
           [-u | --include-untracked] [-a | --all] [<message>]
git stash clear
git stash create [<message>]
git stash store [(-m | --message) <message>] [-q | --quiet] <commit>
git stash export (--print | --to-ref <ref>) [<stash>...]
git stash import <commit>

DESCRIPTION
-----------

`git stash`를 사용하여 워킹 트리와 인덱스의 현재 상태를 기록하지만,
깨끗한 워킹 트리로 돌아가고 싶을 때 사용합니다. 이 명령어는 로컬 변경사항을
저장하고 워킹 트리를 `HEAD` 커밋에 맞게 되돌립니다.

이 명령어로 저장된 변경사항들은 `git stash list`로 목록을 보고,
`git stash show`로 검사하고, `git stash apply`로 (다른 커밋 위에) 복원할 수 있습니다.
인수 없이 `git stash`를 호출하는 것은 `git stash push`와 동일합니다.
기본적으로 스태시는 "WIP on '<branchname>' ..."으로 표시되지만,
만들 때 커맨드 라인에 더 설명적인 메시지를 줄 수 있습니다.

마지막으로 만든 스태시는 `refs/stash`에 저장됩니다. 이전 스태시들은
이 참조의 reflog에서 찾을 수 있으며 일반 reflog 구문(예: `stash@{0}`은 가장 최근에
만들어진 스태시, `stash@{1}`은 그 이전의 스태시, `stash@{2.hours.ago}` 등)으로
이름 붙일 수 있습니다. 스태시는 인덱스 `<n>`만 지정하여 참조할 수도 있습니다 (예: 정수 `<n>`은
`stash@{<n>}`과 동등합니다).

COMMANDS
--------

`push [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-u | --include-untracked] [ -a | --all] [-q | --quiet] [(-m|--message) <message>] [--pathspec-from-file=<file> [--pathspec-file-nul]] [--] [<pathspec>...]`::

	로컬 변경사항을 새 'stash 항목'에 저장하고 HEAD (워킹 트리와 인덱스)로
	되돌립니다.
	_<message>_ 부분은 선택 사항이며,
	저장된 상태와 함께 설명을 제공합니다.
+
빠르게 스냅샷을 만들려면 "push"를 생략할 수 있습니다. 이 모드에서는,
잘못된 서브커맨드가 원치 않는 stash 항목을 만드는 것을 방지하기 위해,
pathspec 요소는 이중 하이픈 `--` 뒤에만 허용됩니다.

`save [-p | --patch] [-S | --staged] [-k | --[no-]keep-index] [-u | --include-untracked] [-a | --all] [-q | --quiet] [<message>]`::

	이 옵션은 `git stash push`에 비해 폐기되었습니다.
	"stash push"와 다른 점은 pathspec을 받을 수 없다는 것입니다.
	대신, 모든 옵션이 아닌 인수는 스태시 메시지를 형성하기 위해
	연결됩니다.

`list [<log-options>]`::

	현재 가지고 있는 스태시 항목 목록을 보여줍니다. 각 'stash 항목'은
	이름 (예: `stash@{0}`은 최신 항목, `stash@{1}`은 그 이전 항목 등),
	항목이 만들어졌을 때의 현재 브랜치 이름, 그리고 항목이 기반으로 한
	커밋에 대한 짧은 설명을 사용하여 나열됩니다.
+
----------------------------------------------------------------
stash@{0}: WIP on submit: 6ebd0e2... Update git-stash documentation
stash@{1}: On master: 9cc0589... Add git-stash
----------------------------------------------------------------
+
이 명령어는 'git log'
명령어에 적용 가능한 옵션들을 사용하여 무엇을 어떻게 보여줄지 제어합니다. linkgit:git-log[1]를 참조하십시오.

`show [-u | --include-untracked | --only-untracked] [<diff-options>] [<stash>]`::

	스태시 항목에 기록된 변경사항을, 저장되었던 내용과 스태시 항목이
	처음 생성되었을 때의 커밋 사이의 diff로 보여줍니다.
	기본적으로 이 명령어는 diffstat를 보여주지만, 'git diff'에 알려진
	어떤 형식도 받아들일 수 있습니다 (예: `git stash show -p stash@{1}`
	두 번째 최신 항목을 패치 형식으로 보기 위해).
	_<diff-option>_이 제공되지 않으면, 기본 동작은
	`stash.showStat` 및 `stash.showPatch` 설정 변수에 의해 결정됩니다.
	`stash.showIncludeUntracked`를 사용하여 `--include-untracked`가
	기본적으로 활성화되는지 설정할 수도 있습니다.

`pop [--index] [-q | --quiet] [<stash>]`::

	단일 스태시된 상태를 스태시 목록에서 제거하고 현재 워킹 트리 상태 위에
	적용합니다. 즉, `git stash push`의 반대 작업을 수행합니다.
	워킹 트리는 인덱스와 일치해야 합니다.
+
상태 적용 시 충돌로 인해 실패할 수 있습니다. 이 경우 스태시 목록에서
	제거되지 않습니다. 충돌을 수동으로 해결하고 나중에 `git stash drop`을
	호출해야 합니다.

`apply [--index] [-q | --quiet] [<stash>]`::

	`pop`과 유사하지만, 스태시 목록에서 상태를 제거하지 않습니다. `pop`과 달리,
	`<stash>`는 `stash push` 또는 `stash create`로 생성된 것처럼 보이는
	어떤 커밋이든 될 수 있습니다.

`branch <branchname> [<stash>]`::

	_<stash>_가 원래 생성되었던 커밋에서 시작하는 _<branchname>_이라는
	새로운 브랜치를 생성하고 체크아웃하며, _<stash>_에 기록된 변경사항을
	새로운 워킹 트리와 인덱스에 적용합니다.
	이것이 성공하고 _<stash>_가 `stash@{<revision>}` 형태의 참조이면,
	그 후 _<stash>_를 삭제합니다.
+
이는 `git stash push`를 실행한 브랜치에서 `git stash apply`가 충돌로 인해
	실패할 정도로 많이 변경되었을 때 유용합니다. 스태시 항목은 `git stash`가
	실행되었을 때의 HEAD였던 커밋 위에 적용되므로, 충돌 없이 원래의
	저장된 상태를 복원합니다.

`clear`::
	모든 스태시 항목을 제거합니다. 이 항목들은 이후
	정리에 대상이 되며 복구가 불가능할 수 있습니다 (복구 가능한 전략은
	'EXAMPLES' 아래를 참조하십시오).

`drop [-q | --quiet] [<stash>]`::
	스태시 항목 목록에서 단일 스태시 항목을 제거합니다.

`create`::

	스태시 항목 (일반 커밋 객체)을 생성하고
	네임스페이스에 저장하지 않고 객체 이름을 반환합니다.
	이것은 스크립트에 유용하도록 의도되었습니다. 아마도 당신이 원하는
	명령어가 아닐 것입니다. 위에서 "push"를 참조하십시오.

`store`::

	'git stash create'로 생성된 스태시 (매달린 머지 커밋)를
	스태시 참조에 저장하고, 스태시 참조 로그를 업데이트합니다.
	이것은 스크립트에 유용하도록 의도되었습니다. 아마도 당신이 원하는
	명령어가 아닐 것입니다. 위에서 "push"를 참조하십시오.

`export ( --print | --to-ref <ref> ) [<stash>...]`::

	지정된 스태시, 또는 지정되지 않은 경우 모든 스태시를
	일반 fetch 및 push 메커니즘으로 전송할 수 있는 커밋 체인으로
	내보낸 다음, `import` 서브커맨드를 사용하여 가져옵니다.

`import <commit>`::
	`export`로 생성되었어야 하는 지정된 커밋에서 지정된 스태시를
	가져와 스태시 목록에 추가합니다. 기존 스태시를 교체하려면
	먼저 `clear`를 사용하십시오.

OPTIONS
-------
`-a`::
`--all`::
	이 옵션은 `push` 및 `save` 명령에서만 유효합니다.
+
무시된 파일과 추적되지 않은 모든 파일도 저장된 다음
`git clean`으로 정리됩니다.

`-u`::
`--include-untracked`::
`--no-include-untracked`::
	`push` 및 `save` 명령과 함께 사용 시,
	추적되지 않은 모든 파일도 저장된 다음 `git clean`으로 정리됩니다.
+
	`show` 명령과 함께 사용 시, 스태시 항목의 추적되지 않은 파일을
	diff의 일부로 보여줍니다.

`--only-untracked`::
	이 옵션은 `show` 명령에서만 유효합니다.
+
	스태시 항목의 추적되지 않은 파일만 diff의 일부로 보여줍니다.

`--index`::
	이 옵션은 `pop` 및 `apply` 명령에서만 유효합니다.
+
	인덱스의 변경사항뿐만 아니라 워킹 트리 변경사항도 복원하려고 시도합니다.
	하지만, 충돌이 발생한 경우 실패할 수 있습니다 (이는 인덱스에 저장되며,
	따라서 원래대로 변경사항을 적용할 수 없습니다).

`--label-ours=<label>`::
`--label-theirs=<label>`::
`--label-base=<label>`::
	이 옵션은 `apply` 명령에서만 유효합니다.
+
	기본값인 "Updated upstream", "Stashed changes", "Stash base" 대신
	지정된 레이블을 충돌 마커에 사용합니다.
	`--label-base`는 merge.conflictStyle=diff3에서만 영향을 줍니다.

`-k`::
`--keep-index`::
`--no-keep-index`::
	이 옵션은 `push` 및 `save` 명령에서만 유효합니다.
+
	이미 인덱스에 추가된 모든 변경사항은 그대로 유지됩니다.

`-p`::
`--patch`::
	이 옵션은 `push` 및 `save` 명령에서만 유효합니다.
+
	HEAD와 워킹 트리 간의 diff에서 저장할 덩어리를
	상호작용적으로 선택합니다. 스태시 항목은 인덱스 상태가
	저장소의 인덱스 상태와 동일하고, worktree에는 상호작용적으로
	선택한 변경사항만 포함되도록 구성됩니다. 선택된 변경사항은
	worktree에서 롤백됩니다. `--patch` 모드 작동 방식은
	linkgit:git-add[1]의 "Interactive Mode" 섹션을 참조하십시오.
+
	`--patch` 옵션은 `--keep-index`를 의미합니다.
	이것을 재정의하려면 `--no-keep-index`를 사용할 수 있습니다.

include::diff-context-options.adoc[]

`-S`::
`--staged`::
	이 옵션은 `push` 및 `save` 명령에서만 유효합니다.
+
	현재 스테이징된 변경사항만 저장합니다. 이것은 기본적인
	`git commit`과 유사하지만, 상태가 현재 브랜치가 아닌 스태시에
	커밋된다는 점이 다릅니다.
+
	`--patch` 옵션이 이 옵션보다 우선합니다.

`--pathspec-from-file=<file>`::
	이 옵션은 `push` 명령에서만 유효합니다.
+
	Pathspec이 커맨드 라인 인수가 아닌 _<file>_에 제공됩니다. _<file>_이
	정확히 `-`이면 표준 입력이 사용됩니다. Pathspec 요소는 LF 또는 CR/LF로
	분리됩니다. Pathspec 요소는 `core.quotePath` 설정 변수에서 설명된 대로
	따옴표로 묶을 수 있습니다 (linkgit:git-config[1] 참조). `--pathspec-file-nul` 및
	글로벌 `--literal-pathspecs`도 참조하십시오.

`--pathspec-file-nul`::
	이 옵션은 `push` 명령에서만 유효합니다.
+
	`--pathspec-from-file`에서만 의미가 있습니다. Pathspec 요소는
	NUL 문자로 분리되며 다른 모든 문자는 문자 그대로 취급됩니다
	(줄 바꿈 및 따옴표 포함).

`-q`::
`--quiet`::
	이 옵션은 `apply`, `drop`, `pop`, `push`,
	`save`, `store` 명령에서만 유효합니다.
+
	조용하게, 피드백 메시지를 억제합니다.

`--print`::
	이 옵션은 `export` 명령에서만 유효합니다.
+
	내보낸 스태시를 나타내는 커밋 체인을 네임스페이스에 저장하지 않고
	생성하고 객체 ID를 표준 출력으로 출력합니다. 이것은 스크립트를 위해
	설계되었습니다.

`--to-ref`::
	이 옵션은 `export` 명령에서만 유효합니다.
+
	내보낸 스태시를 나타내는 커밋 체인을 생성하고 지정된 참조에
	저장합니다.

`--`::
	이 옵션은 `push` 명령에서만 유효합니다.
+
	명확성을 위해 pathspec과 옵션을 구분합니다.

`<pathspec>...`::
	이 옵션은 `push` 명령에서만 유효합니다.
+
	새 스태시 항목은 pathspec과 일치하는 파일에 대한 수정된 상태만
	기록합니다. 그런 다음 인덱스 항목과 워킹 트리 파일도 이 파일들에 대해서만
	HEAD의 상태로 롤백되며, pathspec과 일치하지 않는 파일은 그대로 유지됩니다.
+
	자세한 내용은 linkgit:gitglossary[7]의 'pathspec' 항목을 참조하십시오.

_<stash>_::
	이 옵션은 `apply`, `branch`, `drop`, `pop`,
	`show`, `export` 명령에서만 유효합니다.
+
	`stash@{<revision>}` 형태의 참조입니다. _<stash>_가 제공되지 않으면,
	최신 스태시 (`stash@{0}`)가 가정됩니다.

DISCUSSION
----------

스태시 항목은 커밋으로 표현되며, 해당 커밋의 트리는 워킹 디렉토리의 상태를 기록하고,
첫 번째 부모는 항목이 생성되었을 때의 `HEAD` 커밋입니다. 두 번째 부모의 트리는
항목이 만들어졌을 때의 인덱스의 상태를 기록하며, `HEAD` 커밋의 자식이 됩니다.
조상 그래프는 다음과 같습니다:

            .----W
           /    /
     -----H----I

여기서 `H`는 `HEAD` 커밋, `I`는 인덱스 상태를 기록하는 커밋,
그리고 `W`는 워킹 트리 상태를 기록하는 커밋입니다.


EXAMPLES
--------

Dirty tree로 pull 하기::

무언가 작업 중인데, 현재 작업 중인 내용과 관련된 업스트림 변경사항이
있다는 것을 알게 되었습니다. 로컬 변경사항이 업스트림 변경사항과 충돌하지
않는다면, 단순히 `git pull`을 실행하면 계속 진행할 수 있습니다.
+
하지만, 로컬 변경사항이 업스트림 변경사항과 충돌하는 경우가 있으며,
이때 `git pull`은 변경사항을 덮어쓰는 것을 거부합니다. 이러한 경우,
변경사항을 저장(stash)하고, pull을 수행한 다음, 다시 저장된 것을 풀면 됩니다.
+
----------------------------------------------------------------
$ git pull
 ...
file foobar not up to date, cannot merge.
$ git stash
$ git pull
$ git stash pop
----------------------------------------------------------------

중단된 워크플로우::

무언가 작업 중인데, 상사가 즉시 무언가를 수정해야 한다고 요구합니다.
전통적으로, 임시 브랜치에 변경사항을 저장하기 위해 커밋을 하고,
원래 브랜치로 돌아가 긴급 수정을 했어야 합니다.
+
----------------------------------------------------------------
# ... hack hack hack ...
$ git switch -c my_wip
$ git commit -a -m "WIP"
$ git switch master
$ edit emergency fix
$ git commit -a -m "Fix in a hurry"
$ git switch my_wip
$ git reset --soft HEAD^
# ... continue hacking ...
----------------------------------------------------------------
+
위 작업을 `git stash`를 사용하여 간소화할 수 있습니다.
+
----------------------------------------------------------------
# ... hack hack hack ...
$ git stash
$ edit emergency fix
$ git commit -a -m "Fix in a hurry"
$ git stash pop
# ... continue hacking ...
----------------------------------------------------------------

부분적인 커밋 테스트::

워크 트리에서 두 개 이상의 커밋을 만들고 싶거나, 각 변경사항을
커밋 전에 테스트하고 싶을 때 `git stash push --keep-index`를
사용할 수 있습니다.
+
----------------------------------------------------------------
# ... hack hack hack ...
$ git add --patch foo            # add just first part to the index
$ git stash push --keep-index    # save all other changes to the stash
$ edit/build/test first part
$ git commit -m 'First part'     # commit fully tested change
$ git stash pop                  # prepare to work on all other changes
# ... repeat above five steps until one commit remains ...
$ edit/build/test remaining parts
$ git commit foo -m 'Remaining parts'
----------------------------------------------------------------

향후 사용을 위해 관련 없는 변경사항 저장::

대규모 변경 중 관련 없는 이슈를 발견하여 잊지 않고 수정하고 싶을 때,
해당 변경사항을 만들고, 스테이징한 다음, `git stash push --staged`를
사용하여 향후 사용을 위해 저장할 수 있습니다. 이것은 스테이징된 변경사항을
커밋하는 것과 유사하지만, 커밋은 현재 브랜치가 아닌 스태시에 저장됩니다.
+
----------------------------------------------------------------
# ... hack hack hack ...
$ git add --patch foo           # add unrelated changes to the index
$ git stash push --staged       # save these changes to the stash
# ... hack hack hack, finish current changes ...
$ git commit -m 'Massive'       # commit fully tested changes
$ git switch fixup-branch       # switch to another branch
$ git stash pop                 # to finish work on the saved changes
----------------------------------------------------------------

실수로 지우거나 삭제한 스태시 항목 복구::

실수로 스태시 항목을 삭제하거나 지운 경우, 일반적인 안전 메커니즘을 통해
복구할 수 없습니다. 그러나 다음 명령어를 사용하여 저장소에 아직 있지만
더 이상 접근할 수 없는 스태시 항목 목록을 확인할 수 있습니다.
+
----------------------------------------------------------------
git fsck --unreachable |
grep commit | cut -d\  -f3 |
xargs git log --merges --no-walk --grep=WIP
