git-branch(1)
=============

NAME
----
git-branch - 브랜치를 나열하고, 생성하고, 삭제합니다.

SYNOPSIS
--------
[synopsis]
git branch [--color[=<when>] | --no-color] [--show-current]
	   [-v [--abbrev=<n> | --no-abbrev]]
	   [--column[=<options>] | --no-column] [--sort=<key>]
	   [--merged [<commit>]] [--no-merged [<commit>]]
	   [--contains [<commit>]] [--no-contains [<commit>]]
	   [--points-at <object>] [--format=<format>]
	   [(-r|--remotes) | (-a|--all)]
	   [--list] [<pattern>...]
git branch [--track[=(direct|inherit)] | --no-track] [-f]
	   [--recurse-submodules] <branch-name> [<start-point>]
git branch (--set-upstream-to=<upstream>|-u <upstream>) [<branch-name>]
git branch --unset-upstream [<branch-name>]
git branch (-m|-M) [<old-branch>] <new-branch>
git branch (-c|-C) [<old-branch>] <new-branch>
git branch (-d|-D) [-r] <branch-name>...
git branch --edit-description [<branch-name>]

DESCRIPTION
-----------

`--list`가 주어지거나, 옵션이 아닌 인자가 없을 경우, 기존 브랜치들이 나열됩니다. 현재 브랜치는 녹색으로 강조 표시되고 별표(*)로 표시됩니다. 연결된 작업 트리에 체크아웃된 모든 브랜치는 청록색으로 강조 표시되고 더하기(+) 기호로 표시됩니다. `-r` 옵션은 원격 추적 브랜치를 나열하고, `-a` 옵션은 로컬 및 원격 브랜치를 모두 표시합니다.

`<pattern>`이 주어지면, 해당 패턴은 쉘 와일드카드로 사용되어 일치하는 브랜치만 출력합니다. 여러 패턴이 주어지면, 브랜치는 어떤 패턴과 일치하는 경우에도 표시됩니다.

`<pattern>`을 제공할 때 `--list`를 사용해야 합니다. 그렇지 않으면 명령이 브랜치 생성으로 해석될 수 있습니다.

`--contains`와 함께 사용하면, 지정된 커밋을 포함하는 브랜치만 표시합니다 (즉, 해당 브랜치의 팁 커밋이 지정된 커밋의 후손인 브랜치). `--no-contains`는 이를 반전시킵니다. `--merged`와 함께 사용하면, 지정된 커밋으로 병합된 브랜치만 (즉, 해당 브랜치의 팁 커밋이 지정된 커밋으로부터 도달 가능한 브랜치) 나열됩니다. `--no-merged`와 함께 사용하면, 지정된 커밋으로 병합되지 않은 브랜치만 나열됩니다. _<commit>_ 인자가 누락되면 `HEAD` (즉, 현재 브랜치의 팁)가 기본값으로 사용됩니다.

명령의 두 번째 형식은 _<branch-name>_이라는 새 브랜치 헤드를 생성하고, 현재 `HEAD`를 가리키거나 _<start-point>_가 제공되면 해당 커밋을 가리킵니다. _<start-point>_의 특별한 경우로, _<rev-A>_와 _<rev-B>_의 머지 베이스를 가리키는 `<rev-A>...<rev-B>`를 바로 가리키는 바로가기로 사용할 수 있습니다. _<rev-A>_와 _<rev-B>_ 중 하나를 남겨둘 수 없으며, 이 경우 `HEAD`가 기본값으로 사용됩니다.

이것은 새 브랜치를 생성하지만, 워킹 트리를 해당 브랜치로 전환하지는 않습니다. 새 브랜치로 전환하려면 `git switch <new-branch>`를 사용하십시오.

원격 추적 브랜치에서 로컬 브랜치가 시작될 때, Git은 브랜치를 설정합니다 (구체적으로 `branch.<name>.remote` 및 `branch.<name>.merge` 설정 항목). 이를 통해 `git pull`이 원격 추적 브랜치에서 적절하게 머지할 수 있습니다. 이 동작은 전역 `branch.autoSetupMerge` 설정 플래그를 통해 변경될 수 있습니다. 이 설정은 `--track` 및 `--no-track` 옵션을 사용하여 재정의할 수 있으며, 나중에 `git branch --set-upstream-to`를 사용하여 변경할 수 있습니다.

`-m` 또는 `-M` 옵션과 함께 사용하면, _<old-branch>_는 _<new-branch>_로 이름이 변경됩니다. _<old-branch>_에 해당 reflog가 있는 경우, _<new-branch>_에 맞게 이름이 변경되고, 브랜치 이름 변경을 기억하기 위한 reflog 항목이 생성됩니다. _<new-branch>_가 이미 존재하는 경우, `-M`을 사용하여 이름 변경을 강제해야 합니다.

`-c` 및 `-C` 옵션은 `-m` 및 `-M`과 정확히 동일한 의미를 가지지만, 브랜치가 이름이 변경되는 대신 설정 및 reflog와 함께 새 이름으로 복사됩니다.

`-d` 또는 `-D` 옵션과 함께 사용하면, _<branch-name>_이 삭제됩니다. 삭제할 브랜치를 여러 개 지정할 수 있습니다. 브랜치에 reflog가 있는 경우 reflog도 삭제됩니다.

원격 추적 브랜치를 삭제하려면 `-r`을 `-d`와 함께 사용하십시오. 원격 추적 브랜치는 원격 저장소에 더 이상 존재하지 않거나 `git fetch`가 다시 가져오지 않도록 구성된 경우에만 삭제하는 것이 의미가 있습니다. 또한, 오래된 원격 추적 브랜치를 정리하는 방법으로 `git-remote`의 `prune` 하위 명령을 참조하십시오.

OPTIONS
-------
`-d`::
`--delete`::
	브랜치를 삭제합니다. 브랜치는 업스트림 브랜치 또는 `--track` 또는 `--set-upstream-to`로 설정된 업스트림이 없는 경우 `HEAD`에 완전히 병합되어야 합니다.

`-D`::
	`--delete --force`의 바로가기입니다.

`--create-reflog`::
	브랜치의 reflog를 생성합니다. 이는 브랜치 ref에 대한 모든 변경 사항 기록을 활성화하여 날짜 기반 sha1 표현식 (예: `<branch-name>@{yesterday}`) 사용을 가능하게 합니다. 어느-바레 저장소가 아닌 경우, reflog는 일반적으로 `core.logAllRefUpdates` 구성 옵션에 의해 기본적으로 활성화됩니다. 부정 형태인 `--no-create-reflog`는 이전 `--create-reflog`를 무효화하지만, 현재 `core.logAllRefUpdates` 설정을 무효화하지는 않습니다.

`-f`::
`--force`::
	_<branch-name>_을 _<start-point>_로 재설정합니다. _<branch-name>_이 이미 존재하는 경우에도 마찬가지입니다. `-f`가 없으면 `git branch`는 기존 브랜치를 변경하는 것을 거부합니다.
	`-d` (또는 `--delete`)와 함께 사용하면, 브랜치의 병합 상태에 관계없이 또는 유효한 커밋을 가리키는지 여부에 관계없이 브랜치 삭제를 허용합니다.
	`-m` (또는 `--move`)과 함께 사용하면, 새 브랜치 이름이 이미 존재하는 경우에도 브랜치 이름 변경을 허용하며, `-c` (또는 `--copy`)의 경우에도 동일하게 적용됩니다.
+
`-f`와 함께 `git branch -f <branch-name> [<start-point>]`를 사용하더라도, 해당 리포지토리에 연결된 다른 작업 트리에 체크아웃된 기존 브랜치 _<branch-name>_을 변경하는 것은 거부됩니다.

`-m`::
`--move`::
	브랜치를 이동/이름 변경합니다. 설정 및 reflog도 함께 이동/이름 변경됩니다.

`-M`::
	`--move --force`의 바로가기입니다.

`-c`::
`--copy`::
	브랜치를 복사합니다. 설정 및 reflog도 함께 복사됩니다.

`-C`::
	`--copy --force`의 바로가기입니다.

`--color[=<when>]`::
	브랜치를 색상으로 표시하여 현재, 로컬, 원격 추적 브랜치를 강조 표시합니다.
	값은 `always` (기본값), `never`, 또는 `auto`여야 합니다.

`--no-color`::
	구성 파일이 기본값으로 색상 출력을 제공하는 경우에도, 브랜치 색상을 끕니다.
	`--color=never`와 동일합니다.

`-i`::
`--ignore-case`::
	브랜치 정렬 및 필터링 시 대소문자를 구분하지 않습니다.

`--omit-empty`::
	형식이 빈 문자열로 확장되는 형식화된 ref 이후에 새 줄을 인쇄하지 않습니다.

`--column[=<options>]`::
`--no-column`::
	브랜치 목록을 열로 표시합니다. 옵션 구문은 `column.branch` 구성 변수를 참조하십시오. 옵션 없이 `--column` 및 `--no-column`은 각각 `always` 및 `never`와 동일합니다.
+
이 옵션은 비-상세 모드에서만 적용됩니다.

`--sort=<key>`::
	_<key>_를 기준으로 정렬합니다. `-` 접두사는 값을 내림차순으로 정렬합니다. `--sort=<key>` 옵션을 여러 번 사용할 수 있습니다. 이 경우 마지막 키가 기본 키가 됩니다. 지원되는 키는 linkgit:git-for-each-ref[1]의 키와 동일합니다.
	정렬 순서는 `branch.sort` 변수에 구성된 값 (존재하는 경우) 또는 전체 refname ( `refs/...` 접두사 포함)을 기준으로 정렬하는 것으로 기본값이 설정됩니다. 이는 분리된 `HEAD` (있는 경우), 로컬 브랜치, 마지막으로 원격 추적 브랜치를 나열합니다. linkgit:git-config[1]를 참조하십시오.

`-r`::
`--remotes`::
	원격 추적 브랜치를 나열하거나 삭제합니다 (`-d`와 함께 사용 시).
	선택적 패턴과 일치시키려면 `--list`와 결합합니다.

`-a`::
`--all`::
	원격 추적 브랜치와 로컬 브랜치 모두 나열합니다.
	선택적 패턴과 일치시키려면 `--list`와 결합합니다.

`-l`::
`--list`::
	브랜치를 나열합니다. 선택적 `<pattern>...` (예: `git branch --list 'maint-*'`)과 함께 사용하면, 패턴과 일치하는 브랜치만 나열됩니다.

`--show-current`::
	현재 브랜치의 이름을 출력합니다. 분리된 `HEAD` 상태에서는 아무것도 출력되지 않습니다.

`-v`::
`-vv`::
`--verbose`::
	목록 모드일 때, 각 헤드의 sha1 및 커밋 제목 줄과
	(있는 경우) 업스트림 브랜치와의 관계를 표시합니다. 두 번 사용하면,
	연결된 작업 트리의 경로 (있는 경우)와 업스트림 브랜치의 이름도 표시합니다 (linkgit:git-remote show <remote>도 참조).
	현재 워킹 트리의 `HEAD`는 경로가 인쇄되지 않습니다 (항상 현재 디렉터리).

`-q`::
`--quiet`::
	브랜치 생성 또는 삭제 시 더 조용하게 작동하며, 오류가 아닌 메시지를 억제합니다.

`--abbrev=<n>`::
	커밋 객체 이름을 보여주는 상세 목록에서,
	객체를 고유하게 참조하는 최소 _<n>_개의 16진수 길이가 되는 가장 짧은 접두사를 표시합니다.
	기본값은 7이며 `core.abbrev` 구성 옵션으로 재정의할 수 있습니다.

`--no-abbrev`::
	출력 목록에서 SHA 값을 축약하지 않고 전체 SHA 값을 표시합니다.

`-t`::
`--track[=(direct|inherit)]`::
	새 브랜치를 생성할 때, `branch.<name>.remote` 및
	`branch.<name>.merge` 설정 항목을 설정하여 새 브랜치에 대한 "업스트림" 추적
	설정을 구성합니다. 이
	설정은 git이 `git status` 및 `git branch -v`에서 두 브랜치 간의 관계를
	표시하도록 지시합니다. 또한, 새 브랜치가 체크아웃될 때
	인수 없이 `git pull`이 업스트림에서 풀도록 지시합니다.
+
정확한 업스트림 브랜치는 선택적 인자에 따라 결정됩니다:
`-t`, `--track`, 또는 `--track=direct`는 시작점 브랜치 자체를 업스트림으로 사용함을 의미합니다. `--track=inherit`는 시작점 브랜치의 업스트림 구성을 복사함을 의미합니다.
+
`branch.autoSetupMerge` 구성 변수는 `--track` 또는 `--no-track`이 지정되지 않았을 때 `git switch`, `git checkout`, `git branch`가 어떻게 동작해야 하는지 지정합니다:
+
기본 옵션인 `true`는 시작점이 원격 추적 브랜치인 경우 `--track=direct`가 주어진 것처럼 동작합니다.
`false`는 `--no-track`이 주어진 것처럼 동작합니다. `always`는 `--track=direct`가 주어진 것처럼 동작합니다. `inherit`는 `--track=inherit`가 주어진 것처럼 동작합니다. `simple`은 시작점이 원격 추적 브랜치이고 새 브랜치의 이름이 원격 브랜치의 이름과 같을 때만 `--track=direct`가 주어진 것처럼 동작합니다.
+
`branch.<name>.remote` 및 `branch.<name>.merge` 옵션이 어떻게 사용되는지에 대한 추가적인 논의는 linkgit:git-pull[1] 및 linkgit:git-config[1]를 참조하십시오.

`--no-track`::
	`branch.autoSetupMerge` 구성 변수가 설정되어 있더라도, "업스트림" 구성을 설정하지 않습니다.

`--recurse-submodules`::
	이 옵션은 실험적입니다! `submodule.propagateBranches`가 활성화된 경우, 현재 명령이 하위 모듈을 재귀적으로 처리하도록 합니다. linkgit:git-config[1]의 `submodule.propagateBranches`를 참조하십시오. 현재로서는 브랜치 생성만 지원됩니다.
+
브랜치 생성 시 사용될 때, 슈퍼프로젝트의 _<start-point>_에 있는 모든 하위 모듈뿐 아니라 슈퍼프로젝트에도 새 브랜치 _<branch-name>_이 생성됩니다. 하위 모듈에서는, 브랜치는 슈퍼프로젝트의 _<start-point>_에 있는 하위 모듈 커밋을 가리키지만, 브랜치의 추적 정보는 하위 모듈의 브랜치 및 원격을 기반으로 설정됩니다. 예를 들어 `git branch --recurse-submodules topic origin/main`은 슈퍼프로젝트의 "origin/main"에 있는 하위 모듈 커밋을 가리키는 하위 모듈 브랜치 "topic"을 생성하지만, 하위 모듈의 "origin/main"을 추적합니다.

`--set-upstream`::
	이 옵션은 혼란스러운 문법을 가지고 있었으므로 더 이상 지원되지 않습니다.
	대신 `--track` 또는 `--set-upstream-to`를 사용하십시오.

`-u <upstream>`::
`--set-upstream-to=<upstream>`::
	_<branch-name>_이 _<upstream>_을 _<branch-name>_의 업스트림 브랜치로 간주하도록 _<branch-name>_의 추적 정보를 설정합니다. _<branch-name>_이 지정되지 않으면, 현재 브랜치가 기본값으로 사용됩니다.

`--unset-upstream`::
	_<branch-name>_에 대한 업스트림 정보를 제거합니다. 브랜치가 지정되지 않으면 현재 브랜치가 기본값으로 사용됩니다.

`--edit-description`::
	편집기를 열고 브랜치가 어떤 용도인지 설명하는 텍스트를 편집합니다. 이 텍스트는 다양한 다른 명령 (예: `format-patch`, `request-pull`, `merge` (활성화된 경우))에서 사용됩니다. 여러 줄 설명도 사용할 수 있습니다.

`--contains [<commit>]`::
	_<commit>_ (지정되지 않은 경우 `HEAD`)을 포함하는 브랜치만 나열합니다. `--list`를 암시합니다.

`--no-contains [<commit>]`::
	_<commit>_을 포함하지 않는 브랜치만 나열합니다 (`HEAD`가 지정되지 않은 경우). `--list`를 암시합니다.

`--merged [<commit>]`::
	_<commit>_ (지정되지 않은 경우 `HEAD`)으로부터 도달 가능한 팁을 가진 브랜치만 나열합니다. `--list`를 암시합니다.

`--no-merged [<commit>]`::
	_<commit>_ (지정되지 않은 경우 `HEAD`)으로부터 도달 가능하지 않은 팁을 가진 브랜치만 나열합니다. `--list`를 암시합니다.

`--points-at <object>`::
	_<object>_를 가리키는 브랜치만 나열합니다.

`--format <format>`::
	보여지는 브랜치 ref와 해당 ref가 가리키는 객체로부터 `%(fieldname)`을 보간하는 문자열입니다. _<format>_은 linkgit:git-for-each-ref[1]의 것과 동일합니다.

_<branch-name>_::
	생성하거나 삭제할 브랜치의 이름입니다.
	새 브랜치 이름은 linkgit:git-check-ref-format[1]에 정의된 모든 검사를 통과해야 합니다. 이러한 검사 중 일부는 브랜치 이름에 허용되는 문자를 제한할 수 있습니다.

_<start-point>_::
	새 브랜치 헤드가 가리킬 커밋입니다. 브랜치 이름, 커밋 ID 또는 태그로 지정할 수 있습니다. 이 옵션이 생략되면, 현재 `HEAD`가 대신 사용됩니다.

_<old-branch>_::
	기존 브랜치의 이름입니다. 이 옵션이 생략되면, 현재 브랜치의 이름이 대신 사용됩니다.

_<new-branch>_::
	기존 브랜치의 새 이름입니다. _<branch-name>_과 동일한 제약 조건이 적용됩니다.

EXAMPLES
--------

 알려진 태그에서 개발 시작::
+
------------
$ git clone git://git.kernel.org/pub/scm/.../linux-2.6 my2.6
$ cd my2.6
$ git branch my2.6.14 v2.6.14   <1>
$ git switch my2.6.14
------------
+
<1> 이 단계와 다음 단계는 "checkout -b my2.6.14 v2.6.14"로 하나의 단계로 결합될 수 있습니다.

 필요 없는 브랜치 삭제::
+
------------
$ git clone git://git.kernel.org/.../git.git my.git
$ cd my.git
$ git branch -d -r origin/todo origin/html origin/man   <1>
$ git branch -D test                                    <2>
------------
+
<1> 원격 추적 브랜치 "todo", "html", "man"을 삭제합니다. 다음 `git fetch` 또는 `git pull`은 구성하지 않는 한 다시 생성합니다. linkgit:git-fetch[1]을 참조하십시오.
<2> "test" 브랜치를 삭제합니다. "master" 브랜치 (또는 현재 체크아웃된 다른 브랜치)가 test 브랜치의 모든 커밋을 포함하지 않는 경우에도 삭제됩니다.

 특정 원격 저장소에서 브랜치 나열::
+
------------
$ git branch -r -l '<remote>/<pattern>'                 <1>
$ git for-each-ref 'refs/remotes/<remote>/<pattern>'    <2>
------------
+
<1> `-a`를 사용하면 _<remote>_과 해당 패턴으로 접두사가 붙은 로컬 브랜치가 혼동될 수 있습니다.
<2> `for-each-ref`는 다양한 옵션을 가질 수 있습니다. linkgit:git-for-each-ref[1]을 참조하십시오.

패턴은 일반적으로 따옴표로 묶어야 합니다.

NOTES
-----

즉시 전환하려는 브랜치를 생성하는 경우, `git switch` 명령과 `-c` 옵션을 사용하여 하나의 명령으로 동일한 작업을 수행하는 것이 더 쉽습니다.

`--contains`, `--no-contains`, `--merged`, `--no-merged` 옵션은 네 가지 관련 있지만 다른 목적을 수행합니다:

- `--contains <commit>`은 _<commit>_이 리베이스되거나 수정될 경우 특별한 주의가 필요한 모든 브랜치를 찾는데 사용됩니다. 해당 브랜치는 지정된 _<commit>_을 포함하기 때문입니다.

- `--no-contains <commit>`은 이의 반대입니다. 즉, 지정된 _<commit>_을 포함하지 않는 브랜치입니다.

- `--merged`는 안전하게 삭제할 수 있는 모든 브랜치를 찾는 데 사용됩니다. 해당 브랜치가 `HEAD`에 완전히 포함되기 때문입니다.

- `--no-merged`는 `HEAD`로 병합될 후보인 브랜치를 찾는 데 사용됩니다. 해당 브랜치가 `HEAD`에 완전히 포함되지 않기 때문입니다.
