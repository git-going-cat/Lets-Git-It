git-checkout-index(1)
=====================

NAME
----
git-checkout-index - 인덱스에서 워킹 트리로 파일 복사


SYNOPSIS
--------
[verse]
'git checkout-index' [-u] [-q] [-a] [-f] [-n] [--prefix=<string>]
		   [--stage=<number>|all]
		   [--temp]
		   [--ignore-skip-worktree-bits]
		   [-z] [--stdin]
		   [--] [<file>...]

DESCRIPTION
-----------
인덱스에서 지정된 모든 파일을 워킹 디렉토리로 복사합니다 (기존 파일은 덮어쓰지 않습니다).

OPTIONS
-------
-u::
--index::
	인덱스 파일에서 체크아웃된 항목의 stat 정보를 업데이트합니다.

-q::
--quiet::
	파일이 존재하거나 인덱스에 없을 경우 조용히 처리합니다.

-f::
--force::
	기존 파일을 강제로 덮어씁니다.

-a::
--all::
	skip-worktree 비트가 설정된 파일을 제외하고 인덱스의 모든 파일을 체크아웃합니다 (참조: `--ignore-skip-worktree-bits`).
	명시적인 파일 이름과 함께 사용할 수 없습니다.

-n::
--no-create::
	새 파일을 체크아웃하지 않고, 이미 체크아웃된 파일만 새로고침합니다.

--prefix=<string>::
	파일을 생성할 때 <string> (일반적으로 후행 / 를 포함하는 디렉토리)을 앞에 붙입니다.

--stage=<number>|all::
	병합되지 않은 항목을 체크아웃하는 대신, 지정된 스테이지의 파일들을 복사합니다. <number>는 1에서 3 사이여야 합니다.
	참고: --stage=all은 --temp를 자동으로 포함합니다.

--temp::
	파일을 워킹 디렉토리로 복사하는 대신, 내용을 임시 파일에 씁니다. 임시 파일 이름과 연결 정보는 stdout으로 기록됩니다.

--ignore-skip-worktree-bits::
	skip-worktree 비트가 설정된 파일을 포함하여 모든 파일을 체크아웃합니다.

--stdin::
	명령줄에서 경로 목록을 받는 대신, 표준 입력에서 경로 목록을 읽습니다. 기본적으로 경로는 LF (즉, 줄당 하나의 경로)로 구분됩니다.

-z::
	`--stdin`에서만 의미가 있습니다. 경로는 LF 대신 NUL 문자로 구분됩니다.

\--::
	더 이상 인수를 옵션으로 해석하지 않습니다.

플래그의 순서는 중요했지만, 이제는 중요하지 않습니다.

`git checkout-index`만 실행하면 아무 작업도 수행되지 않습니다. 아마도 `git checkout-index -a`를 의도했을 것입니다. 그리고 강제로 실행하려면 `git checkout-index -f -a`를 사용하면 됩니다.

직관성은 목표가 아닙니다. 반복성이 목표입니다. "인수가 없으면 아무 작업도 하지 않음" 동작의 이유는 스크립트에서 다음과 같이 수행할 수 있기 때문입니다:

----------------
$ find . -name '*.h' -print0 | xargs -0 git checkout-index -f --
----------------

이것은 기존의 모든 `*.h` 파일을 캐시된 복사본으로 강제로 대체합니다. 빈 명령줄이 "모두"를 의미했다면, 이것은 인덱스의 모든 것을 강제로 새로고침했을 것이며, 이는 의도가 아니었습니다. 하지만 'git checkout-index'는 --stdin을 허용하므로 다음을 사용하는 것이 더 빠를 것입니다:

----------------
$ find . -name '*.h' -print0 | git checkout-index -f -z --stdin
----------------

`--`는 나머지가 파일 이름이 될 것임을 알 때 좋은 습관입니다. 파일 이름이 예를 들어 `-a`와 같은 경우 문제를 방지할 것입니다. 스크립트에서는 `--`를 사용하는 것이 좋은 정책입니다.


Using --temp or --stage=all
---------------------------
`--temp` (또는 `--stage=all`에 의해 암시됨)를 사용할 때
'git checkout-index'는 체크아웃되는 각 인덱스 항목에 대해 임시 파일을 생성합니다. 인덱스는 stat 정보로 업데이트되지 않습니다. 이러한 옵션은 호출자가 병합되지 않은 파일이 외부 병합 도구에 의해 처리될 수 있도록 병합되지 않은 모든 항목의 모든 스테이지가 필요한 경우 유용할 수 있습니다.

임시 파일 이름과 추적된 경로 이름의 연결을 제공하는 목록이 stdout으로 작성됩니다. 목록 형식에는 두 가지 변형이 있습니다:

    . tempname TAB path RS
+
첫 번째 형식은 `--stage`가 생략되거나 `--stage=all`이 아닌 경우에 사용됩니다. tempname 필드는 파일 내용을 보유하는 임시 파일 이름이고 path는 인덱스의 추적된 경로 이름입니다. 요청된 항목만 출력됩니다.

    . stage1temp SP stage2temp SP stage3tmp TAB path RS
+
두 번째 형식은 `--stage=all`인 경우에 사용됩니다. 세 가지 스테이지 임시 필드 (stage1temp, stage2temp, stage3temp)는 인덱스에 스테이지 항목이 있는 경우 해당 임시 파일 이름을 나열하거나 스테이지 항목이 없는 경우 `.`을 나열합니다. 스테이지 0 항목만 있는 경로는 항상 출력에서 제외됩니다.

두 형식 모두에서 RS (레코드 구분 기호)는 기본적으로 개행 문자이지만 -z가 명령줄에서 전달된 경우 null 바이트가 됩니다. 임시 파일 이름은 항상 안전한 문자열입니다. 디렉토리 구분 기호나 공백 문자를 절대 포함하지 않습니다. path 필드는 항상 현재 디렉토리에 상대적이며 임시 파일 이름은 항상 최상위 디렉토리에 상대적입니다.

임시 파일로 복사되는 객체가 심볼릭 링크인 경우 링크의 내용이 일반 파일에 기록됩니다. 이 정보를 활용하는 것은 최종 사용자 또는 Porcelain에 달려 있습니다.


EXAMPLES
--------
체크아웃된 파일만 업데이트하고 새로고침하려면::
+
----------------
$ git checkout-index -n -f -a && git update-index --ignore-missing --refresh
----------------

'git checkout-index'를 사용하여 "전체 트리를 내보내기"::
	prefix 기능은 'git checkout-index'를 "트리로 내보내기" 기능으로 사용하는 것을 기본적으로 사소하게 만듭니다.
	원하는 트리를 인덱스로 읽어온 다음 다음을 수행합니다:
+
----------------
$ git checkout-index --prefix=git-export-dir/ -a
----------------
+
'git checkout-index'는 인덱스를 지정된 디렉토리로 "내보냅니다".
+
마지막 "/"는 중요합니다. 내보낸 이름은 지정된 문자열 앞에 문자 그대로 붙여집니다. 다음 예와 대조됩니다.

접두사를 사용하여 파일 내보내기::
+
----------------
$ git checkout-index --prefix=.merged- Makefile
----------------
+
이것은 `Makefile`의 현재 캐시된 복사본을 `.merged-Makefile` 파일로 체크아웃합니다.
