git-symbolic-ref(1)
===================

NAME
----
git-symbolic-ref - 기호 참조 읽기, 수정 및 삭제

SYNOPSIS
--------
[verse]
'git symbolic-ref' [-m <reason>] <name> <ref>
'git symbolic-ref' [-q] [--short] [--no-recurse] <name>
'git symbolic-ref' --delete [-q] <name>

DESCRIPTION
-----------
인수가 하나 주어지면, 주어진 기호 참조가 어떤 브랜치 헤드를 참조하는지 읽고 `.git/` 디렉토리를 기준으로 상대적인 경로를 출력합니다.
일반적으로 워킹 트리가 어느 브랜치에 있는지 확인하기 위해 `<name>` 인수로 `HEAD`를 사용합니다.

인수가 두 개 주어지면, `<name>`이라는 기호 참조를 생성하거나, 주어진 브랜치 `<ref>`를 가리키도록 업데이트합니다.

`--delete`와 추가 인수가 주어지면, 주어진 기호 참조를 삭제합니다.

기호 참조는 `ref: refs/`로 시작하는 문자열을 저장하는 일반 파일입니다.
예를 들어, `.git/HEAD`는 `ref: refs/heads/master`라는 내용을 가진 일반 파일입니다.

OPTIONS
-------

-d::
--delete::
	기호 참조 `<name>`을 삭제합니다.

-q::
--quiet::
	`<name>`이 기호 참조가 아니라 분리된 HEAD인 경우 오류 메시지를 출력하지 않고, 성공하지 못했음을 나타내는 0이 아닌 상태 코드로 조용히 종료합니다.

--short::
	`<name>`의 값을 기호 참조로 보여줄 때, `refs/heads/master`에서 `master`와 같이 값을 축약하려고 시도합니다.

--recurse::
--no-recurse::
	`<name>`의 값을 기호 참조로 보여줄 때, `<name>`이 다른 기호 참조를 참조하는 경우, 결과가 더 이상 기호 참조를 가리키지 않을 때까지 이러한 기호 참조 체인을 따라갑니다 (`--recurse`가 기본값).
	`--no-recurse`는 단일 레벨의 기호 참조만 역참조한 후 중지합니다.

-m::
	`<reason>`으로 `<name>`에 대한 reflog를 업데이트합니다.
	이는 기호 참조를 생성하거나 업데이트할 때만 유효합니다.

NOTES
-----
과거에는 `.git/HEAD`가 `refs/heads/master`를 가리키는 심볼릭 링크였습니다.
다른 브랜치로 전환하려면 `ln -sf refs/heads/newbranch .git/HEAD`를 사용했고,
어느 브랜치에 있는지 확인하려면 `readlink .git/HEAD`를 사용했습니다.
하지만 심볼릭 링크는 완전히 이식 가능하지 않으므로, 이제는 사용되지 않으며 기본적으로 기호 참조(위에서 설명한 대로)가 사용됩니다.

`git symbolic-ref`는 기호 참조의 내용이 올바르게 출력되면 상태 코드 0으로,
요청된 이름이 기호 참조가 아니면 상태 코드 1로,
다른 오류가 발생하면 상태 코드 128로 종료됩니다.
