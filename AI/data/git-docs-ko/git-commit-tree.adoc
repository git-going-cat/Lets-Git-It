git-commit-tree(1)
==================

NAME
----
git-commit-tree - 새로운 커밋 객체 생성


SYNOPSIS
--------
[verse]
'git commit-tree' <tree> [(-p <parent>)...]
'git commit-tree' [(-p <parent>)...] [-S[<keyid>]] [(-m <message>)...]
		  [(-F <file>)...] <tree>


DESCRIPTION
-----------
이것은 일반 사용자가 직접 실행해야 하는 것이 아닙니다. 대신 linkgit:git-commit[1]을 참조하십시오.

제공된 트리 객체를 기반으로 새로운 커밋 객체를 생성하고 새로운 커밋 객체 id를 표준 출력으로 내보냅니다. 로그 메시지는 `-m` 또는 `-F` 옵션이 주어지지 않는 한 표준 입력에서 읽어옵니다.

`-m` 및 `-F` 옵션은 순서에 상관없이 원하는 만큼 제공할 수 있습니다. 커밋 로그 메시지는 옵션이 제공된 순서대로 구성됩니다.

커밋 객체는 원하는 만큼의 부모를 가질 수 있습니다. 부모가 하나만 있는 경우 일반적인 커밋입니다. 둘 이상의 부모를 가지면 해당 커밋은 여러 히스토리 라인 간의 머지입니다. 초기(루트) 커밋은 부모가 없습니다.

트리는 워킹 트리의 특정 디렉토리 상태를 나타내는 반면, 커밋은 "시간"의 해당 상태를 나타내고 거기까지 어떻게 도달했는지 설명합니다.

일반적으로 커밋은 새로운 "HEAD" 상태를 식별하며, Git은 해당 상태에 대한 노트를 어디에 저장하든 신경 쓰지 않지만, 실제로는 `.git/HEAD`가 가리키는 파일에 결과를 쓰므로 마지막 커밋된 상태를 항상 볼 수 있습니다.

OPTIONS
-------
<tree>::
	기존 트리 객체.

-p <parent>::
	각 `-p`는 부모 커밋 객체의 id를 나타냅니다.

-m <message>::
	커밋 로그 메시지의 한 문단. 여러 번 제공할 수 있으며 각 `<message>`는 자체 문단이 됩니다.

-F <file>::
	주어진 파일에서 커밋 로그 메시지를 읽습니다. 표준 입력에서 읽으려면 `-`를 사용합니다. 여러 번 제공할 수 있으며 각 파일의 내용은 자체 문단이 됩니다.

-S[<keyid>]::
--gpg-sign[=<keyid>]::
--no-gpg-sign::
	커밋에 GPG 서명합니다. `keyid` 인수는 선택 사항이며
	커미터 식별자로 기본 설정됩니다. 지정된 경우 공백 없이 옵션에 붙여야 합니다. `--no-gpg-sign`은 명령줄에서 이전에 제공된 `--gpg-sign` 옵션을 무효화하는 데 유용합니다.

Commit Information
------------------

커밋은 다음을 캡슐화합니다:

- 모든 부모 객체 id
- 작성자 이름, 이메일 및 날짜
- 커미터 이름, 이메일 및 커밋 시간.

커밋 주석은 stdin에서 읽어옵니다. 변경 로그
항목이 "<" 리디렉션을 통해 제공되지 않으면 'git commit-tree'는
입력이 제공되고 ^D로 종료될 때까지 기다립니다.
