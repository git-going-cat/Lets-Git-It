git-status(1)
=============

NAME
----
git-status - 워킹 트리의 상태를 보여줍니다.


SYNOPSIS
--------

[synopsis]
git status [<options>] [--] [<pathspec>...]

DESCRIPTION
-----------
인덱스 파일과 현재 HEAD 커밋 간의 차이가 있는 경로, 워킹 트리와 인덱스 파일 간의 차이가 있는 경로, 그리고 Git에서 추적되지 않는(그리고 linkgit:gitignore[5]에 의해 무시되지 않는) 워킹 트리의 경로를 표시합니다. 첫 번째는 `git commit`을 실행하여 _커밋할 것_이고, 두 번째와 세 번째는 `git commit`을 실행하기 전에 `git add`를 실행하여 _커밋할 수 있는 것_입니다.

OPTIONS
-------

`-s`::
`--short`::
	결과를 짧은 형식으로 출력합니다.

`-b`::
`--branch`::
	짧은 형식에서도 브랜치 및 추적 정보를 보여줍니다.

`--show-stash`::
	현재 스태시(stash)된 항목의 수를 보여줍니다.

`--porcelain[=<version>]`::
	스크립트에서 쉽게 파싱할 수 있는 형식으로 결과를 출력합니다.
	이것은 짧은 출력과 유사하지만, Git 버전 및 사용자 구성에 관계없이 안정적으로 유지됩니다. 자세한 내용은 아래를 참조하십시오.
+
 _<version>_ 매개변수는 형식 버전을 지정하는 데 사용됩니다.
 이 매개변수는 선택 사항이며 기본값은 원본 버전 `v1` 형식입니다.

`--long`::
	긴 형식으로 결과를 출력합니다. 이것이 기본값입니다.

`-v`::
`--verbose`::
	변경된 파일 이름 외에도 커밋될 준비가 된 텍스트 변경 사항을 보여줍니다.
	(즉, `git diff --cached`의 출력과 같습니다). `-v`가 두 번 지정되면, 아직 스테이징되지 않은 워킹 트리의 변경 사항도 보여줍니다.
	(즉, `git diff`의 출력과 같습니다).

`-u[<mode>]`::
`--untracked-files[=<mode>]`::
	추적되지 않은 파일을 보여줍니다.
+
--
 mode 매개변수는 추적되지 않은 파일을 처리하는 데 사용됩니다.
 기본값은 `all`이며 선택 사항입니다. 지정된 경우
 옵션에 붙여야 합니다 (예: `-uno`, 하지만 `-u no`는 아님).

가능한 옵션은 다음과 같습니다.

`no`:: 추적되지 않은 파일을 보여주지 않습니다.
`normal`:: 추적되지 않은 파일 및 디렉토리를 보여줍니다.
`all`:: 추적되지 않은 디렉토리 내의 개별 파일도 보여줍니다.

`-u` 옵션을 사용하지 않으면 추적되지 않은 파일 및 디렉토리가 표시됩니다 (즉, `normal`을 지정한 것과 동일). 새로 생성된 파일을 추가하는 것을 잊지 않도록 돕기 위해서입니다.
파일 시스템에서 추적되지 않은 파일을 찾는 데 추가 작업이 필요하므로 이 모드는 대형 워킹 트리에서 시간이 걸릴 수 있습니다.
지원되는 경우 추적되지 않은 캐시 및 분할 인덱스 활성화를 고려하십시오 ( `git update-index --untracked-cache` 및 `git update-index --split-index` 참조).
그렇지 않으면 `git status`가 추적되지 않은 파일 없이 더 빠르게 반환되도록 `no`를 사용할 수 있습니다.
Boolean 값 `true`에 대한 모든 일반적인 철자는 `normal`로, `false`는 `no`로 간주됩니다.

기본값은 linkgit:git-config[1]에 설명된 `status.showUntrackedFiles` 구성 변수를 사용하여 변경할 수 있습니다.
--

`--ignore-submodules[=<when>]`::
	하위 모듈의 변경 사항을 무시합니다. _<when>_은
	`none`, `untracked`, `dirty` 또는 `all`(기본값)이 될 수 있습니다.
`none`;; 하위 모듈이 추적되지 않거나 수정된 파일을 포함하거나 HEAD가 슈퍼프로젝트에 기록된 커밋과 다른 경우 하위 모듈이 수정된 것으로 간주하며, linkgit:git-config[1] 또는 linkgit:gitmodules[5]의 `ignore` 옵션 설정을 재정의하는 데 사용할 수 있습니다.
`untracked`;; 하위 모듈이 추적되지 않은 내용만 포함하는 경우 (하지만 수정된 내용은 계속 스캔함) 더티(dirty)로 간주되지 않습니다.
`dirty`;; 하위 모듈 워킹 트리의 모든 변경 사항을 무시합니다.
	슈퍼프로젝트에 저장된 커밋의 변경 사항만 표시됩니다 (1.7.0 이전의 동작).
`all`;; 하위 모듈의 모든 변경 사항을 숨깁니다.
	(`status.submoduleSummary` 구성 옵션이 설정된 경우 하위 모듈 요약 출력을 억제합니다).

`--ignored[=<mode>]`::
	무시된 파일도 보여줍니다.
+
--
 mode 매개변수는 무시된 파일을 처리하는 데 사용됩니다.
 기본값은 `traditional`이며 선택 사항입니다.

가능한 옵션은 다음과 같습니다.

`traditional`:: 무시된 파일과 디렉토리를 보여줍니다.
`--untracked-files=all`이 지정된 경우를 제외하고,
	무시된 디렉토리 내의 개별 파일이 표시됩니다.
`no`:: 무시된 파일을 보여주지 않습니다.
`matching`:: 무시 패턴과 일치하는 무시된 파일 및 디렉토리를 보여줍니다.
+
명시적으로 무시 패턴과 일치하는 경로는 표시됩니다. 디렉토리가 무시 패턴과 일치하면
	해당 디렉토리는 표시되지만 무시된 디렉토리의 경로는 표시되지 않습니다. 디렉토리가 무시 패턴과 일치하지 않지만 모든 내용이 무시되면
	 디렉토리는 표시되지 않고 모든 내용은 표시됩니다.
--

`-z`::
	항목을 _LF_ 대신 _NUL_로 종료합니다. 이것은 다른 형식 없이 `--porcelain=v1` 출력 형식을 의미합니다.

`--column[=<options>]`::
`--no-column`::
	추적되지 않은 파일을 열로 표시합니다. `column.status` 구성 변수를 참조하십시오.
	옵션 구문. `--column`과 `--no-column`은 각각 `always`와 `never`에 해당합니다.

`--ahead-behind`::
`--no-ahead-behind`::
	브랜치가 상위 브랜치에 대해 앞서 있거나 뒤져 있는 상세 카운트를 표시하거나 표시하지 않습니다. 기본값은 `true`입니다.

`--renames`::
`--no-renames`::
	사용자 구성에 관계없이 이름 변경 감지를 켜거나 끕니다.
	linkgit:git-diff[1] `--no-renames`도 참조하십시오.

`--find-renames[=<n>]`::
	이름 변경 감지를 켭니다. 선택적으로 유사도 임계값을 설정할 수 있습니다.
	linkgit:git-diff[1] `--find-renames`도 참조하십시오.

`<pathspec>...`::
	linkgit:gitglossary[7]의 'pathspec' 항목을 참조하십시오.

OUTPUT
------
이 명령의 출력은 커밋 템플릿 주석으로 사용하도록 설계되었습니다.
기본 긴 형식은 사람이 읽을 수 있고, 장황하며, 설명적으로 설계되었습니다.
그 내용과 형식은 언제든지 변경될 수 있습니다.

출력에 언급된 경로는 많은 다른 Git 명령과 달리 서브디렉토리에서 작업 중인 경우 현재 디렉토리에 상대적입니다 (자르기 및 붙여넣기를 돕기 위해 의도적입니다). 아래의 status.relativePaths 구성 옵션을 참조하십시오.

Short Format
~~~~~~~~~~~~

짧은 형식에서 각 경로의 상태는 다음 형식 중 하나로 표시됩니다.

	<xy> <path>
	<xy> <orig-path> -> <path>

여기서 _<orig-path>_는 이름이 변경되거나 복사된 내용의 원본 위치입니다. _<orig-path>_는 항목이 이름이 변경되거나 복사될 때만 표시됩니다. _<xy>_는 두 글자 상태 코드 `XY`입니다.

필드(_->_ 포함)는 단일 공백으로 구분됩니다. 파일 이름에 공백 또는 기타 인쇄 불가능한 문자가 포함된 경우 해당 필드는 C 문자열 리터럴 방식으로 따옴표로 묶입니다: ASCII 큰따옴표 (34) 문자로 둘러싸고 내부 특수 문자는 백슬래시로 이스케이프합니다.

이 형식을 사용하여 세 가지 다른 유형의 상태가 표시되며, 각 상태는 _<xy>_ 구문을 다르게 사용합니다.

* 병합이 발생하고 병합이 성공했거나 병합 상황 외부인 경우, `X`는 인덱스의 상태를, `Y`는 워킹 트리의 상태를 보여줍니다.
* 병합 충돌이 발생했고 아직 해결되지 않은 경우, `X`와 `Y`는 병합의 각 헤드에 의해 도입된 상태를 공통 조상에 대해 보여줍니다. 이러한 경로는 _병합되지 않은(unmerged)_ 상태라고 합니다.
* 경로가 추적되지 않은 경우, `X`와 `Y`는 항상 동일하며, 인덱스에 알려져 있지 않기 때문입니다. 추적되지 않은 경로에는 `??`가 사용됩니다. `--ignored`가 사용되지 않는 한 무시된 파일은 나열되지 않습니다. 사용된 경우 무시된 파일은 `!!`로 표시됩니다.

여기서 _병합_이라는 용어는 기본 `--merge` 전략, cherry-picks 및 병합 메커니즘을 사용하는 다른 모든 것을 포함합니다.

다음 표에서 이 세 가지 클래스는 별도의 섹션으로 표시되며, 처음 두 섹션에서 추적된 경로를 보여주는 경우 `X` 및 `Y` 필드에 이러한 문자가 사용됩니다.

' ':: 수정되지 않음
`M`:: 수정됨
`T`:: 파일 유형 변경됨 (일반 파일, 기호 링크 또는 하위 모듈)
`A`:: 추가됨
`D`:: 삭제됨
`R`:: 이름 변경됨
`C`:: 복사됨 (status.renames 구성 옵션이 "copies"로 설정된 경우)
`U`:: 업데이트되었지만 병합되지 않음

[cols="^1m,^1m,<2",options="header"]
|===
|X        |  Y     |의미
|         |[AMD]   |업데이트되지 않음
|M        |[ MTD]  |인덱스에서 업데이트됨
|T        |[ MTD]  |인덱스에서 유형 변경됨
|A        |[ MTD]  |인덱스에 추가됨
|D        |        |인덱스에서 삭제됨
|R        |[ MTD]  |인덱스에서 이름 변경됨
|C        |[ MTD]  |인덱스에서 복사됨
|[MTARC]  |        |인덱스와 워킹 트리가 일치
|[ MTARC] |M       |인덱스 이후 워킹 트리가 변경됨
|[ MTARC] |T       |인덱스 이후 워킹 트리 유형이 변경됨
|[ MTARC] |D       |워킹 트리에서 삭제됨
|         |R       |워킹 트리에서 이름 변경됨
|         |C       |워킹 트리에서 복사됨
|D        |D       |병합되지 않음, 양쪽 모두 삭제됨
|A        |U       |병합되지 않음, 우리 쪽에서 추가됨
|U        |D       |병합되지 않음, 상대방에서 삭제됨
|U        |A       |병합되지 않음, 상대방에서 추가됨
|D        |U       |병합되지 않음, 우리 쪽에서 삭제됨
|A        |A       |병합되지 않음, 양쪽 모두 추가됨
|U        |U       |병합되지 않음, 양쪽 모두 수정됨
|?        |?       |추적되지 않음
|!        |!       |무시됨
|===

하위 모듈은 더 많은 상태를 가지며 대신 보고합니다.

`M`:: 하위 모듈의 HEAD가 인덱스의 기록과 다릅니다.
`m`:: 하위 모듈에 수정된 내용이 있습니다.
`?`:: 하위 모듈에 추적되지 않은 파일이 있습니다.

이는 하위 모듈 내의 수정된 내용 또는 추적되지 않은 파일을 슈퍼프로젝트에서 `git add`를 통해 추가하여 커밋을 준비할 수 없기 때문입니다.

`m` 및 `?`는 재귀적으로 적용됩니다. 예를 들어, 하위 모듈 내의 중첩된 하위 모듈에 추적되지 않은 파일이 포함된 경우, 이것도 `?`로 보고됩니다.

`-b`가 사용되면 짧은 형식 상태 앞에 다음 줄이 옵니다.

[synopsis]
{empty}## <branchname> <tracking-info>


Porcelain Format Version 1
~~~~~~~~~~~~~~~~~~~~~~~~~~

버전 1 porcelain 형식은 짧은 형식과 유사하지만, Git 버전 간의 역호환성이 없는 방식으로 변경되거나 사용자 구성에 따라 변경되지 않습니다. 이는 스크립트에서 파싱하는 데 이상적입니다.
짧은 형식에 대한 위 설명은 몇 가지 예외를 제외하고 porcelain 형식에도 적용됩니다.

1. 사용자의 `color.status` 구성은 존중되지 않습니다. 색상은 항상 꺼져 있습니다.

2. 사용자의 `status.relativePaths` 구성은 존중되지 않습니다. 표시되는 경로는 항상 저장소 루트에 상대적입니다.

기계 파싱에 권장되는 대안 `-z` 형식도 있습니다. 해당 형식에서 상태 필드는 동일하지만 몇 가지 다른 사항이 변경됩니다. 첫째, `->`는 이름 변경 항목에서 생략되고 필드 순서가 반전됩니다 (예: `from -> to`가 `to from`이 됨). 둘째, _NUL_ (ASCII 0)이 각 파일 이름 뒤에 오며, 공백 대신 필드 구분자로 사용되고 줄 끝 문자를 대체합니다 (하지만 공백은 상태 필드와 첫 번째 파일 이름을 구분합니다). 셋째, 특수 문자가 포함된 파일 이름은 특별히 형식화되지 않으며 따옴표나 백슬래시 이스케이프가 수행되지 않습니다.

모든 하위 모듈 변경 사항은 단일 `?` 대신 수정된 `M`으로 보고됩니다.

Porcelain Format Version 2
~~~~~~~~~~~~~~~~~~~~~~~~~~

버전 2 형식은 워킹 트리의 상태와 변경된 항목에 대해 더 자세한 정보를 추가합니다. 버전 2는 쉽게 파싱할 수 있는 선택적 헤더의 확장 가능한 집합도 정의합니다.

헤더 줄은 `#`으로 시작하며 특정 명령줄 인수에 응답하여 추가됩니다. 파서는 인식하지 못하는 헤더를 무시해야 합니다.

Branch Headers
^^^^^^^^^^^^^^

`--branch`가 지정되면 현재 브랜치에 대한 정보가 포함된 일련의 헤더 줄이 인쇄됩니다.

[cols="<1,<1",options="header"]
|===
|Line                                     |Notes
|`# branch.oid <commit> \| (initial)`     |Current commit.
|`# branch.head <branch> \| (detached)`   |Current branch.
|`# branch.upstream <upstream-branch>`    |If upstream is set.
|`# branch.ab +<ahead> -<behind>`         |If upstream is set and
					  the commit is present.
|===

Stash Information
^^^^^^^^^^^^^^^^^

`--show-stash`가 지정되면 0이 아닌 경우 스태시 항목 수를 보여주는 한 줄이 인쇄됩니다.

    # stash <N>

Changed Tracked Entries
^^^^^^^^^^^^^^^^^^^^^^^

헤더 다음에 추적된 항목에 대한 일련의 줄이 인쇄됩니다. 변경 유형에 따라 세 가지 다른 줄 형식이 사용될 수 있습니다. 추적된 항목은 정의되지 않은 순서로 인쇄됩니다. 파서는 어떤 순서로든 3가지 줄 유형의 혼합을 허용해야 합니다.

일반 변경 항목은 다음 형식을 갖습니다.

[synopsis]
1 <XY> <sub> <mH> <mI> <mW> <hH> <hI> <path>

이름 변경 또는 복사된 항목은 다음 형식을 갖습니다.

[synopsis]
2 <XY> <sub> <mH> <mI> <mW> <hH> <hI> <X><score> <path><sep><origPath>

[cols="<1,<1a",options="header"]
|===
|Field       | Meaning

|_<XY>_
| 짧은 형식에서 설명된 스테이징 및 언스테이징된 XY 값을 포함하는 2자 필드
	(변경되지 않은 경우 공백 대신 "." 사용).
|_<sub>_
| 하위 모듈 상태를 설명하는 4자 필드.
"N..." 항목이 하위 모듈이 아닌 경우.
`S<c><m><u>` 항목이 하위 모듈인 경우.

* _<c>_는 커밋이 변경된 경우 "C"이고, 그렇지 않으면 "."입니다.
* _<m>_은 추적된 변경 사항이 있는 경우 "M"이고, 그렇지 않으면 "."입니다.
* _<u>_는 추적되지 않은 변경 사항이 있는 경우 "U"이고, 그렇지 않으면 "."입니다.
|_<mH>_       |HEAD의 8진수 파일 모드.
|_<mI>_       |인덱스의 8진수 파일 모드.
|_<mW>_       |워킹 트리의 8진수 파일 모드.
|_<hH>_       |HEAD의 객체 이름.
|_<hI>_       |인덱스의 객체 이름.
|_<X><score>_ |이름 변경 또는 복사 점수 (소스와 대상 간의 유사도
	 퍼센티지를 나타냄). 예: "R100" 또는 "C75".
|_<path>_
|경로명. 이름 변경/복사된 항목에서는 대상 경로입니다.
|_<sep>_
|`-z` 옵션이 사용되면 두 경로명은 _NUL_ (ASCII 0x00) 바이트로 구분됩니다. 그렇지 않으면 _TAB_ (ASCII 0x09) 바이트가 구분합니다.
|_<origPath>_
|HEAD 또는 인덱스의 커밋에 있는 경로명.
이것은 이름 변경/복사된 항목에만 있으며,
	 이름 변경/복사된 내용이 어디에서 왔는지 알려줍니다.
|===

병합되지 않은 항목은 다음 형식을 따릅니다. 첫 번째 문자는 일반 변경 항목과 구별하기 위한 "u"입니다.

[synopsis]
u <XY> <sub> <m1> <m2> <m3> <mW> <h1> <h2> <h3> <path>

[cols="<1,<1a",options="header"]
|===
|Field       |Meaning
|_<XY>_      |짧은 형식에서 설명된 대로 충돌 유형을 설명하는 2자 필드.
|_<sub>_     |위에서 설명한 대로 하위 모듈 상태를 설명하는 4자 필드.
|_<m1>_      |스테이지 1의 8진수 파일 모드.
|_<m2>_      |스테이지 2의 8진수 파일 모드.
|_<m3>_      |스테이지 3의 8진수 파일 모드.
|_<mW>_      |워킹 트리의 8진수 파일 모드.
|_<h1>_      |스테이지 1의 객체 이름.
|_<h2>_      |스테이지 2의 객체 이름.
|_<h3>_      |스테이지 3의 객체 이름.
|_<path>_    |경로명.
|===

Other Items
^^^^^^^^^^^

추적된 항목 뒤에 (요청 시) 워킹 트리에서 발견된 추적되지 않은 항목, 그리고 무시된 항목에 대한 일련의 줄이 인쇄됩니다.

Untracked items have the following format:

    ? <path>

Ignored items have the following format:

    ! <path>

Pathname Format Notes and -z
^^^^^^^^^^^^^^^^^^^^^^^^^^^^

`-z` 옵션이 주어지면, 경로명은 그대로 인쇄되고 따옴표 없이 _NUL_ (ASCII 0x00) 바이트로 끝나며 줄이 구분됩니다.

`-z` 옵션이 없으면, "비정상적인" 문자가 포함된 경로명은 `core.quotePath` 구성 변수 (linkgit:git-config[1] 참조)에 설명된 대로 따옴표로 묶입니다.


CONFIGURATION
-------------

이 명령은 출력을 색칠하기 위해 `color.status` (또는 `status.color` -- 둘 다 같은 의미이며 후자는 호환성을 위해 유지됨) 및 `color.status.<slot>` 구성 변수를 사용합니다.

`status.relativePaths` 구성 변수가 false로 설정된 경우, 표시되는 모든 경로는 현재 디렉토리가 아닌 저장소 루트에 상대적입니다.

`status.submoduleSummary`가 0이 아닌 숫자 또는 true( -1 또는 무제한 숫자와 동일)로 설정된 경우, 긴 형식에 대해 하위 모듈 요약이 활성화되고 수정된 하위 모듈에 대한 커밋 요약이 표시됩니다 (linkgit:git-submodule[1]의 `--summary-limit` 옵션 참조). status 명령의 요약 출력은 `diff.ignoreSubmodules`가 `all`로 설정되어 있거나 `submodule.<name>.ignore=all`로 설정된 하위 모듈에 대해서만 억제된다는 점에 유의하십시오. 무시된 하위 모듈에 대한 요약도 보려면 `--ignore-submodules=dirty` 명령줄 옵션 또는 유사한 출력을 보여주지만 이러한 설정을 존중하지 않는 `git submodule summary` 명령을 사용하십시오.

BACKGROUND REFRESH
------------------

기본적으로 `git status`는 인덱스를 자동으로 새로 고치고, 워킹 트리에서 캐시된 통계 정보를 업데이트하고 결과를 기록합니다. 인덱스를 기록하는 것은 엄격하게 필요하지 않은 최적화입니다 (`status` 자체적으로 값을 계산하지만, 이를 기록하는 것은 후속 프로그램이 우리의 계산을 반복하는 것을 방지하기 위함입니다). `status`가 백그라운드에서 실행될 때, 쓰기 중에 보유하는 잠금은 다른 동시 프로세스와 충돌하여 실패할 수 있습니다. 백그라운드에서 `status`를 실행하는 스크립트는 `git --no-optional-locks status`를 고려해야 합니다 (자세한 내용은 linkgit:git[1] 참조).

UNTRACKED FILES AND PERFORMANCE
-------------------------------

`git status`는 대용량 워킹 트리에서 추적되지 않은 파일 및 디렉토리를 검색해야 하는 경우 매우 느릴 수 있습니다. 작업을 피하거나 이전 Git 명령의 캐시된 결과를 사용함으로써 이를 가속화하기 위한 다양한 구성 옵션을 사용할 수 있습니다. 모든 사람에게 적합한 단일 최적 설정은 없습니다. 도움을 드리기 위해 관련 옵션의 요약을 나열하겠습니다. 하지만 목록을 보기 전에 `git status`를 다시 실행해 보는 것이 좋습니다. 구성에서 이미 `git status` 결과 캐싱을 사용하고 있어 후속 실행에서 더 빨라질 수 있기 때문입니다.

* `--untracked-files=no` 플래그 또는
	`status.showUntrackedFiles=no` 구성 (둘 다 위 참조):
	`git status`가 추적되지 않은 파일을 보고하지 않도록 지정합니다. 이것이 가장 빠른 옵션입니다. `git status`는 추적되지 않은 파일을 나열하지 않으므로, 새 파일을 만들고 수동으로 `git add`해야 하는지 기억해야 합니다.

* `advice.statusUoption=false` (linkgit:git-config[1] 참조):
	이 변수를 `false`로 설정하면 추적되지 않은 파일을 열거하는 데 2초 이상 걸릴 때 제공되는 경고 메시지가 비활성화됩니다. 대규모 프로젝트에서는 더 오래 걸릴 수 있으며 사용자가 이미 절충안을 수락했을 수 있습니다 (예: `-uno`가 사용자에게 허용 가능한 옵션이 아닐 수 있음). 이 경우 경고 메시지를 발행할 이유가 없으며, 그러한 경우 경고를 비활성화하는 것이 가장 좋을 수 있습니다.

* `core.untrackedCache=true` (linkgit:git-update-index[1] 참조):
	추적되지 않은 캐시 기능을 활성화하고 이전 `git status` 명령 이후 수정된 디렉토리만 검색합니다.
	Git은 각 디렉토리 내의 추적되지 않은 파일 집합을 기억하고, 디렉토리가 수정되지 않았다면
	그 안의 추적되지 않은 파일 집합도 변경되지 않았다고 가정합니다. 이것은 모든 디렉토리의 내용을 열거하는 것보다 훨씬 빠르지만,
	Git은 여전히 수정된 디렉토리 집합을 검색해야 하므로 비용이 전혀 들지 않는 것은 아닙니다. 추적되지 않은 캐시는
	`.git/index` 파일에 저장됩니다. 추적되지 않은 파일 검색 비용이 감소하는 것은 인덱스 크기가 증가하고
	업데이트를 유지하는 비용으로 인해 약간 상쇄됩니다. 일반적으로 감소된 검색 시간은 추가 크기만큼의 가치가 있습니다.

* `core.untrackedCache=true` 및 `core.fsmonitor=true` 또는
	`core.fsmonitor=<hook-command-pathname>` (linkgit:git-update-index[1] 참조): 추적되지 않은 캐시와 FSMonitor 기능을 모두 활성화하고 이전 `git status` 명령 이후 수정된 디렉토리만 검색합니다.
	이것은 추적되지 않은 캐시만 사용하는 것보다 빠릅니다. Git은 수정된 디렉토리 집합을 피할 수도 있기 때문입니다.
	Git은 최근에 변경된 디렉토리의 정확한 집합만 열거하면 됩니다. FSMonitor 기능은
	추적되지 않은 캐시 없이도 활성화할 수 있지만, 이 경우 이득이 크게 줄어듭니다.

추적되지 않은 캐시 및/또는 FSMonitor 기능을 켜면 여러 `git status` 명령 후에 캐시가 워밍업되어 개선된 명령 시간을 볼 수 있다는 점에 유의하십시오. 이것은 정상입니다.
