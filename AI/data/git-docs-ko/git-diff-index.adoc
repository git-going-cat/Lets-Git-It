git-diff-index(1)
=================

NAME
----
git-diff-index - 트리와 워킹 트리 또는 인덱스 비교


SYNOPSIS
--------
[verse]
'git diff-index' [-m] [--cached] [--merge-base] [<common-diff-options>] <tree-ish> [<path>...]

DESCRIPTION
-----------
트리 객체에 있는 블롭(blob)의 내용과 모드를 워킹 트리에서 해당 추적 파일과 비교하거나,
인덱스에서 해당 경로와 비교합니다. <path> 인수가 제공되면, 해당 패턴과 일치하는 경로만 비교합니다.
그렇지 않으면 모든 추적된 파일이 비교됩니다.

OPTIONS
-------
include::diff-options.adoc[]

<tree-ish>::
	비교 대상이 될 트리 객체의 ID입니다.

--cached::
	디스크에 있는 파일을 전혀 고려하지 않습니다.

--merge-base::
	<tree-ish>를 직접 비교하는 대신, <tree-ish>와 HEAD 간의 병합 기본(merge base)을 사용합니다.
	<tree-ish>는 커밋이어야 합니다.

-m::
	기본적으로, 인덱스에 기록되었지만 체크아웃되지 않은 파일은 삭제된 것으로 보고됩니다.
	이 플래그는 'git diff-index'가 체크아웃되지 않은 모든 파일이 최신 상태라고 말하게 합니다.

include::diff-format.adoc[]

OPERATING MODES
---------------
전적으로 인덱스 파일을 신뢰할지(`--cached` 플래그 사용) 또는
stat 상태와 일치하지 않는 파일은 "잠정적으로 변경됨"으로 표시하도록 diff 로직에 요청할지
선택할 수 있습니다. 이 두 작업 모두 매우 유용합니다.

CACHED MODE
-----------
`--cached`가 지정되면 다음과 같이 질문할 수 있습니다.

	HEAD와 현재 인덱스 내용( 'git write-tree'를 사용하여 작성할 내용) 간의 차이점을 보여줘.

예를 들어, 워킹 디렉토리 작업을 하고, 일부 파일을 인덱스에서 업데이트했으며,
커밋할 준비가 되었다고 가정해 봅시다. 새 트리 객체를 작성하고 그 방식으로 비교하지 않고도
정확히 *무엇*을 커밋할 것인지 보고 싶다면, 다음을 수행합니다.

	git diff-index --cached HEAD

예: `commit.c`를 `git-commit.c`로 이름을 바꾸었고, 인덱스 파일에서 변경 사항을 적용하기 위해
`update-index`를 실행했다고 가정해 봅시다. `git diff-files`는 인덱스 파일이
워킹 디렉토리와 일치하므로 아무것도 표시하지 않습니다. 하지만 'git diff-index'를 수행하면 표시됩니다.

  torvalds@ppc970:~/git> git diff-index --cached HEAD
  :100644 000000 4161aecc6700a2eb579e842af0b7f22b98443f74 0000000000000000000000000000000000000000 D	commit.c
  :000000 100644 0000000000000000000000000000000000000000 4161aecc6700a2eb579e842af0b7f22b98443f74 A	git-commit.c

위의 내용이 이름 변경임을 쉽게 알 수 있습니다.

사실, `git diff-index --cached`는 항상 'git write-tree'를 수행하고
그것과 비교하는 것과 완전히 동일해야 합니다. 다만, 단순히 현재 상태를 확인하려는
경우에는 이것이 훨씬 더 편리합니다.

따라서 `git diff-index --cached`를 수행하는 것은 기본적으로 "내가 커밋을 위해 이미 표시한 것은 무엇이며,
이전 트리와 무엇이 다른가?"라고 스스로에게 물어볼 때 매우 유용합니다.

NON-CACHED MODE
---------------
"Non-cached" 모드는 다른 접근 방식을 취하며, 두 가지 모드 중 잠재적으로 더 유용한 모드입니다.
왜냐하면 이 모드의 작동 방식은 'git write-tree' + 'git diff-tree'로 에뮬레이션할 수 없기 때문입니다.
따라서 이것이 기본 모드입니다. Non-cached 버전은 다음과 같은 질문을 합니다.

  HEAD와 현재 체크아웃된 트리(인덱스 내용 *및* 업데이트되지 않은 파일) 간의 차이점을 보여줘.

이것 또한 명백히 매우 유용한 질문입니다. 왜냐하면 무엇을 커밋할 수 있는지 알려주기 때문입니다.
다시 말하지만, 출력은 'git diff-tree -r'의 출력과 완벽하게 일치하지만, 약간의 변형이 있습니다.

변형은 일부 파일이 인덱스와 일치하지 않으면 해당 파일에 대한 백업 저장소 항목이 없고,
"무효" SHA1을 사용하여 이를 표시한다는 것입니다. 예를 들어, `kernel/sched.c`를 편집했지만
아직 'git update-index'를 실행하지 않았다고 가정해 봅시다. 새 상태와 관련된 "객체"가 없으며,
다음과 같은 결과가 나옵니다.

  torvalds@ppc970:~/v2.6/linux> git diff-index --abbrev HEAD
  :100644 100644 7476bb5ba 000000000 M	kernel/sched.c

즉, 트리가 변경되었고, `kernel/sched.c`가 최신 상태가 아니며 새로운 내용이 포함될 수 있음을 보여줍니다.
무효 SHA1은 실제 diff를 얻으려면 객체 간 diff를 수행하는 대신 워킹 디렉토리의 객체를 직접 봐야 함을 의미합니다.

참고: 이와 같은 다른 명령과 마찬가지로, 'git diff-index'는 실제로 파일 내용을 전혀 보지 않습니다.
따라서 `kernel/sched.c`가 실제로 변경되지 않았고 단지 건드리기만 했을 수도 있습니다.
어떤 경우든, 인덱스가 동기화되도록 'git update-index'를 실행해야 한다는 알림입니다.

참고: "업데이트된 파일"으로 표시되는 파일과 "워킹 디렉토리에서 여전히 변경된" 파일이
함께 나타날 수 있습니다. "업데이트된" 파일은 유효한 SHA1을 표시하고, "인덱스와 동기화되지 않은" 파일은
항상 특별한 무효 SHA1을 가지므로 어떤 파일이 어떤 상태인지 항상 알 수 있습니다.
