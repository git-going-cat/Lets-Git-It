git-apply(1)
============

NAME
----
git-apply - Apply a patch to files and/or to the index


SYNOPSIS
--------
[verse]
'git apply' [--stat] [--numstat] [--summary] [--check]
	  [--index | --intent-to-add] [--3way] [--ours | --theirs | --union]
	  [--apply] [--no-add] [--build-fake-ancestor=<file>] [-R | --reverse]
	  [--allow-binary-replacement | --binary] [--reject] [-z]
	  [-p<n>] [-C<n>] [--inaccurate-eof] [--recount] [--cached]
	  [--ignore-space-change | --ignore-whitespace]
	  [--whitespace=(nowarn|warn|fix|error|error-all)]
	  [--exclude=<path>] [--include=<path>] [--directory=<root>]
	  [--verbose | --quiet] [--unsafe-paths] [--allow-empty] [<patch>...]

DESCRIPTION
-----------
제공된 diff 출력("패치")을 읽어 파일에 적용합니다.
저장소 내의 하위 디렉토리에서 실행할 때, 해당 디렉토리 외부의 패치된 경로는 무시됩니다.
`--index` 옵션을 사용하면 패치가 인덱스에도 적용되며,
`--cached` 옵션을 사용하면 패치가 인덱스에만 적용됩니다.
이러한 옵션이 없으면, 명령은 패치를 파일에만 적용하며 Git 저장소를 요구하지 않습니다.

이 명령은 패치를 적용하지만 커밋을 생성하지는 않습니다.
`linkgit:git-format-patch[1]`으로 생성되거나 이메일로 받은 패치로
커밋을 생성하려면 linkgit:git-am[1]을 사용하십시오.

OPTIONS
-------
<patch>...::
	패치를 읽어 들일 파일입니다. 표준 입력을 읽으려면 '-'를 사용할 수 있습니다.

--stat::
	패치를 적용하는 대신 입력에 대한 diffstat을 출력합니다. "apply" 기능을 끕니다.

--numstat::
	`--stat`과 유사하지만, 추가 및 삭제된 줄의 수를 십진수 표기법으로
	표시하고 경로명을 축약 없이 출력하여 기계 친화적으로 만듭니다.
	이진 파일의 경우 `0 0`이라고 말하는 대신 두 개의 `-`를 출력합니다. "apply" 기능을 끕니다.

--summary::
	패치를 적용하는 대신, git diff 확장 헤더에서 얻은 정보(예: 생성, 이름 변경, 모드 변경)의
	축약된 요약을 출력합니다. "apply" 기능을 끕니다.

--check::
	패치를 적용하는 대신, 패치가 현재 워킹 트리 및/또는 인덱스 파일에
	적용 가능한지 확인하고 오류를 감지합니다. "apply" 기능을 끕니다.

--index::
	패치를 인덱스와 워킹 트리 모두에 적용합니다. (`--check`가 활성화된 경우
	둘 모두에 깔끔하게 적용되는지만 확인합니다.)
	참고로 `--index`는 관련 경로에 대한 인덱스 항목과 워킹 트리 복사본이
	동일해야 한다고 예상합니다 (내용과 파일 모드와 같은 메타데이터가 일치해야 함).
	패치가 인덱스와 워킹 트리 자체에는 깔끔하게 적용 되더라도,
	일치하지 않으면 오류를 발생시킵니다.

--cached::
	워킹 트리를 건드리지 않고 인덱스에만 패치를 적용합니다.
	`--check`가 활성화된 경우, 인덱스 항목에 깔끔하게 적용되는지만 확인합니다.

-N::
--intent-to-add::
	패치를 워킹 트리에만 적용할 때, 나중에 인덱스에 추가될 새 파일을
	표시합니다 (linkgit:git-add[1]의 `--intent-to-add` 옵션 참조).
	`--index` 또는 `--cached`가 사용된 경우 이 옵션은 무시되며, Git 저장소 외부에서는 효과가 없습니다.
	`--index`는 `--3way`와 같은 다른 옵션에 의해 암시될 수 있음에 유의하십시오.

-3::
--3way::
	패치가 적용되어야 하는 블롭의 식별자를 기록하고 해당 블롭이 로컬에
	사용 가능한 경우 3-방향 머지를 시도합니다. 충돌 마커를 워킹 트리의
	파일에 남겨 사용자가 해결하도록 할 수 있습니다. 이 옵션은
	`--cached` 옵션이 사용되지 않는 한 `--index` 옵션을 암시하며,
	`--reject` 옵션과 호환되지 않습니다.
	`--cached` 옵션과 함께 사용될 때, 모든 충돌은 캐시에서 더 높은 단계에 남겨집니다.

--ours::
--theirs::
--union::
	파일에 충돌을 남기는 대신, 우리 쪽 (또는 상대방 또는 양쪽) 줄을
	선호하여 충돌을 해결합니다. `--3way`가 필요합니다.

--build-fake-ancestor=<file>::
	최신 'git diff' 출력에는 원본 버전을 식별하는 데 도움이 되는
	각 블롭에 대한 '인덱스 정보'가 포함되어 있습니다.
	이 플래그가 주어지고 원본 블롭이 로컬에 사용 가능한 경우,
	해당 블롭을 포함하는 임시 인덱스를 빌드합니다.
+
순수 모드 변경(인덱스 정보가 없는)이 발견되면,
	정보는 현재 인덱스에서 읽어옵니다.

-R::
--reverse::
	패치를 역으로 적용합니다.

--reject::
	원자성을 위해, 'git apply'는 기본적으로 패치의 일부 훔(hunk)이
	적용되지 않으면 전체 패치를 실패시키고 워킹 트리를 건드리지 않습니다.
	이 옵션은 적용 가능한 패치 부분을 적용하고, 거부된 훔은
	해당하는 *.rej 파일에 남겨둡니다.

-z::
	`--numstat`이 주어진 경우, 경로명을 변경하지 않고 NUL로 종료되는
	기계 판독 가능 형식을 사용합니다.
+
이 옵션이 없으면, "특이한" 문자가 포함된 경로명은
	`core.quotePath` 구성 변수 (linkgit:git-config[1] 참조)에 설명된 대로
	인용됩니다.

-p<n>::
	전통적인 diff 경로에서 <n>개의 선행 경로 구성 요소(슬래시로 구분됨)를 제거합니다.
	예를 들어, `-p2`를 사용하면 `a/dir/file`에 대한 패치가 `file`에 직접 적용됩니다.
	기본값은 1입니다.

-C<n>::
	변경 전후의 각 변경에 대해 최소 <n> 줄의 주변 문맥이 일치하는지 확인합니다.
	주변 문맥이 적은 경우, 모든 문맥이 일치해야 합니다.
	기본적으로 문맥은 무시되지 않습니다.

--unidiff-zero::
	기본적으로 'git apply'는 적용될 패치가 최소 한 줄의 문맥을 가진
	unified diff라고 가정합니다. 이는 좋은 안전 조치이지만,
	`--unified=0`으로 생성된 diff를 적용할 때 문제가 발생합니다.
	이러한 검사를 우회하려면 `--unidiff-zero`를 사용하십시오.
+
주의: 위에 명시된 이유로 인해 문맥 없는 패치의 사용은 권장되지 않습니다.

--apply::
	위에 "apply" 기능을 끕니다"라고 표시된 옵션 중 하나를 사용하는 경우,
	'git apply'는 패치를 실제로 적용하지 않고 요청된 정보를 읽고 출력합니다.
	패치도 적용하려면 해당 플래그 뒤에 이 플래그를 주십시오.

--no-add::
	패치를 적용할 때, 패치로 인한 추가 사항을 무시합니다.
	두 파일 간의 공통 부분을 추출하는 데 사용할 수 있습니다.
	먼저 해당 파일에 대해 'diff'를 실행하고 이 옵션으로 결과를 적용하면,
	삭제 부분은 적용되지만 추가 부분은 적용되지 않습니다.

--allow-binary-replacement::
--binary::
	과거에는 사용자로부터 명시적인 허가가 없으면 이진 패치 적용을 허용하지 않았으며,
	이 플래그가 그 방법이었습니다. 현재는 항상 이진 패치 적용을 허용하므로,
	이 플래그는 아무 효과가 없습니다.

--exclude=<path-pattern>::
	주어진 경로 패턴과 일치하는 파일에 대한 변경을 적용하지 마십시오.
	이는 패치셋을 가져올 때 특정 파일이나 디렉토리를 제외하려는 경우 유용할 수 있습니다.

--include=<path-pattern>::
	주어진 경로 패턴과 일치하는 파일에 대한 변경을 적용하십시오.
	이는 패치셋을 가져올 때 특정 파일이나 디렉토리를 포함하려는 경우 유용할 수 있습니다.
+
`--exclude`와 `--include` 패턴이 사용될 때, 명령어 라인에 나타나는
	순서대로 검사되며, 첫 번째 일치 항목이 각 경로에 대한 패치 사용 여부를 결정합니다.
	포함/제외 패턴과 일치하지 않는 경로에 대한 패치는 기본적으로 사용됩니다.
	명령어 라인에 포함 패턴이 없는 경우 사용되며, 포함 패턴이 있는 경우 무시됩니다.

--ignore-space-change::
--ignore-whitespace::
	패치를 적용할 때, 필요한 경우 문맥 줄의 공백 변경을 무시합니다.
	문맥 줄은 공백을 유지하며, `--whitespace` 옵션 값과 관계없이
	공백 수정이 적용되지 않습니다. 새로운 줄은 여전히 수정됩니다.

--whitespace=<action>::
	패치를 적용할 때, 공백 오류가 있는 새 줄 또는 수정된 줄을 감지합니다.
	어떤 것이 공백 오류로 간주되는지는 `core.whitespace` 구성으로 제어됩니다.
	기본적으로, 후행 공백 (공백으로만 이루어진 줄 포함)과 줄의 초기 들여쓰기 바로 뒤에 오는
	공백 문자는 공백 오류로 간주됩니다.
+
기본적으로, 명령은 경고 메시지를 출력하지만 패치를 적용합니다.
	통계 및 패치 미적용을 위해 `git apply`가 사용될 때, 기본값은 `nowarn`입니다.
+
이 동작을 제어하기 위해 다양한 `<action>` 값을 사용할 수 있습니다:
+
* `nowarn`은 후행 공백 경고를 끕니다.
* `warn`은 몇 가지 오류에 대해 경고를 출력하지만, 패치를 그대로 적용합니다 (기본값).
* `fix`는 몇 가지 오류에 대해 경고를 출력하고, 수정한 후 패치를 적용합니다 (`strip`은 동의어입니다 -- 도구는
	후행 공백 문자만을 오류로 간주했으며, 수정은 이를 '제거'하는 것이었지만, 최신 Git은 더 많은 것을 합니다).
* `error`는 몇 가지 오류에 대해 경고를 출력하고, 패치 적용을 거부합니다.
* `error-all`은 `error`와 유사하지만 모든 오류를 표시합니다.

--inaccurate-eof::
	특정 상황에서 일부 'diff' 버전은 파일 끝의 누락된 새 줄을
	정확하게 탐지하지 못합니다. 결과적으로, 그러한 'diff' 프로그램으로 생성된 패치는
	불완전한 줄을 올바르게 기록하지 못합니다. 이 옵션은 이 버그를 우회하여
	그러한 패치를 적용하는 지원을 추가합니다.

-v::
--verbose::
	진행 상황을 stderr로 보고합니다. 기본적으로 현재 적용 중인 패치에 대한
	메시지만 출력됩니다. 이 옵션은 추가 정보가 보고되도록 합니다.

-q::
--quiet::
	stderr 출력을 억제합니다. 패치 상태 및 진행 상황에 대한 메시지는
	표시되지 않습니다.

--recount::
	훔 헤더의 줄 수를 신뢰하지 않고, 패치를 검사하여 추론합니다 (예:
	훔 헤더를 적절하게 조정하지 않고 패치를 편집한 후).

--directory=<root>::
	모든 파일 이름 앞에 <root>를 붙입니다. "-p" 인수가 전달된 경우,
	새 루트를 붙이기 전에 적용됩니다.
+
예를 들어, `a/git-gui.sh`를 `b/git-gui.sh`로 업데이트하는 패치는
	워킹 트리 파일 `modules/git-gui/git-gui.sh`에 `git apply --directory=modules/git-gui`를
	실행하여 적용할 수 있습니다.

--unsafe-paths::
	기본적으로, 워킹 영역 외부 (Git 제어 워킹 트리 또는 "git apply"가 GNU
	patch의 대체로 사용될 때 현재 작업 디렉토리)에 영향을 미치는 패치는
	실수로 간주되어 거부됩니다 (또는 악의적인 것으로).
+
"더 나은 GNU patch"로 git apply를 사용할 때, 사용자는 안전 확인을
	재정의하기 위해 `--unsafe-paths` 옵션을 전달할 수 있습니다. 이 옵션은
	`--index` 또는 `--cached`가 사용될 때 효과가 없습니다.

--allow-empty::
	차이가 없는 패치에 대한 오류 반환을 방지합니다. 이는 빈 패치와
	커밋 텍스트만 포함하는 패치를 포함합니다.

SUBMODULES
----------
패치에 서브모듈 변경이 포함된 경우 'git apply'는 이러한 변경을 다음과 같이 처리합니다.

`--index`가 지정되면 (명시적으로 또는 암시적으로), 패치가 적용되려면
	서브모듈 커밋이 인덱스와 정확히 일치해야 합니다.
	서브모듈이 체크아웃된 경우, 이러한 체크아웃은 완전히 무시됩니다.
	즉, 최신 상태이거나 깨끗할 필요가 없으며 업데이트되지도 않습니다.

`--index`가 지정되지 않으면, 패치의 서브모듈 커밋은 무시되고,
	해당 하위 디렉토리의 존재 또는 부재만 확인되고 (가능한 경우) 업데이트됩니다.
