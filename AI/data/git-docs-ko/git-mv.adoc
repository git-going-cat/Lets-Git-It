git-mv(1)
=========

NAME
----
git-mv - 파일을, 디렉토리를, 또는 심볼릭 링크를 이동하거나 이름을 변경한다.


SYNOPSIS
--------

[synopsis]
git mv [-v] [-f] [-n] [-k] <source> <destination>
git mv [-v] [-f] [-n] [-k] <source>... <destination-directory>

DESCRIPTION
-----------
파일, 디렉토리, 또는 심볼릭 링크를 이동하거나 이름을 변경합니다.

첫 번째 형식에서는 _<source>_ (존재해야 하며 파일, 심볼릭 링크 또는 디렉토리여야 함)의 이름을 _<destination>_ 으로 변경합니다.
두 번째 형식에서는 _<destination-directory>_ 에 기존 디렉토리가 있어야 하며; 주어진 소스들이 이 디렉토리로 이동됩니다.

작업이 성공적으로 완료되면 인덱스가 업데이트되지만, 변경 사항은 여전히 커밋되어야 합니다.

OPTIONS
-------
`-f`::
`--force`::
	_<destination>_ 이 존재하는 경우에도 파일의 이름 변경 또는 이동을 강제합니다.
`-k`::
	오류를 초래할 수 있는 이동 또는 이름 변경 작업을 건너뜁니다. 소스가 존재하지 않거나 Git에서 제어하지 않는 경우, 또는 `-f`가 주어지지 않은 상태에서 기존 파일을 덮어쓰게 되는 경우 오류가 발생합니다.
`-n`::
`--dry-run`::
	아무 작업도 수행하지 않고, 발생할 수 있는 일만 보여줍니다.

`-v`::
`--verbose`::
	이동되는 파일의 이름을 보고합니다.

SUBMODULES
----------
gitfile (Git 버전 1.7.8 이상으로 클론된 경우)을 사용하여 서브모듈을 이동하면 gitfile 및 core.worktree 설정이 업데이트되어 서브모듈이 새 위치에서 작동하도록 합니다.
또한 linkgit:gitmodules[5] 파일의 `submodule.<name>.path` 설정을 업데이트하고 해당 파일을 스테이징 영역에 추가하려고 시도합니다 (`-n`이 사용되지 않은 경우).

BUGS
----
슈퍼프로젝트 업데이트가 채워진 서브모듈을 이동할 때마다 (예: 이동 전후 커밋 간 전환 시) 이전 위치에 오래된 서브모듈 체크아웃이 남아 있고 새 위치에 빈 디렉토리가 나타납니다. 새 위치에서 서브모듈을 다시 채우려면 사용자가 이후에 "git submodule update"를 실행해야 합니다. 이전 디렉토리를 제거하는 것은 gitfile을 사용하는 경우에만 안전합니다. 그렇지 않으면 서브모듈의 히스토리도 삭제됩니다. 재귀적 서브모듈 업데이트가 구현되면 두 단계 모두 불필요해질 것입니다.
