git-cat-file(1)
===============

NAME
----
git-cat-file - 저장소 객체의 내용 또는 세부 정보 제공

SYNOPSIS
--------
[verse]
'git cat-file' <type> <object>
'git cat-file' (-e | -p | -t | -s) <object>
'git cat-file' (--textconv | --filters)
	     [<rev>:<path|tree-ish> | --path=<path|tree-ish> <rev>]
'git cat-file' (--batch | --batch-check | --batch-command) [--batch-all-objects]
	     [--buffer] [--follow-symlinks] [--unordered]
	     [--textconv | --filters] [-Z]

DESCRIPTION
-----------
하나 이상의 객체의 내용 또는 크기, 유형, 델타 정보와 같은 기타 속성을 출력합니다.

이 명령어는 `--batch` 계열의 옵션이 지정되었는지 여부에 따라 두 가지 모드로 작동할 수 있습니다.

비 배치 모드에서는 명령줄에서 지정된 객체에 대한 정보를 제공합니다.

배치 모드에서는 표준 입력에서 인수가 읽힙니다.

OPTIONS
-------
<object>::
	표시할 객체의 이름입니다.
	객체 이름을 명시하는 방법에 대한 더 완전한 목록은
	linkgit:gitrevisions[7]의 "SPECIFYING REVISIONS" 섹션을 참조하십시오.

-t::
	내용 대신 `<object>`가 식별하는 객체 유형을 표시합니다.

-s::
	내용 대신 `<object>`가 식별하는 객체 크기를 표시합니다. `--use-mailmap` 옵션과 함께 사용하면,
	메일맵 메커니즘을 사용하여 식별자를 대체한 후 업데이트된 객체의 크기를 표시합니다.

-e::
	`<object>`가 존재하고 유효한 객체이면 0으로 종료합니다.
	`<object>`가 잘못된 형식인 경우 0이 아닌 상태로 종료하고 stderr에 오류를 출력합니다.

-p::
	`<object>`의 유형에 따라 내용을 보기 좋게 출력합니다.

<type>::
	일반적으로 이는 `<object>`의 실제 유형과 일치하지만,
	주어진 `<object>`에서 쉽게 역참조될 수 있는 유형을 요청하는 것도 허용됩니다.
	예를 들어, 트리를 포함하는 커밋 객체를 `<object>`로 "tree"를 요청하거나,
	이를 가리키는 태그 객체를 `<object>`로 "blob"을 요청하는 것입니다.

--mailmap::
--no-mailmap::
--use-mailmap::
--no-use-mailmap::
       메일맵 파일을 사용하여 작성자, 커미터 및 태거의 이름과
       이메일 주소를 표준 이름과 이메일 주소로 매핑합니다.
       linkgit:git-shortlog[1]을 참조하십시오.

--textconv::
	textconv 필터로 변환된 내용으로 표시합니다. 이 경우,
	`<object>`는 `<tree-ish>:<path>` 또는 `:<path>` 형식이어야 하며,
	인덱스에 기록된 `<path>`의 내용에 필터를 적용합니다.

--filters::
	현재 워킹 트리에서 구성된 필터로 변환된 내용으로 표시합니다.
	(즉, 얼룩 필터, 줄 끝 변환 등). 이 경우 `<object>`는
	`<tree-ish>:<path>` 또는 `:<path>` 형식이어야 합니다.

--filter=<filter-spec>::
--no-filter::
	출력되는 객체 목록에서 객체를 생략합니다. 이 옵션은
	배치 모드 중 하나와 함께 사용해야 합니다. 배치 모드에서 명시적으로 요청된
	객체 중 (예: `--batch`, `--batch-check`) 표준 입력을 통해 객체를 읽는 모드에서
	생략된 객체는 "filtered"로 보고됩니다. `--batch-all-objects` 모드에서
	생략된 객체는 전혀 출력되지 않습니다. '<filter-spec>'은 다음 중 하나일 수 있습니다:
+
'--filter=blob:none' 형태는 모든 blob을 생략합니다.
+
'--filter=blob:limit=<n>[kmg]' 형태는 n 바이트 이상의 크기를 가진 blob을 생략합니다.
	n은 0일 수 있습니다. k, m, g 접미사는 각각 KiB, MiB, GiB 단위의 이름을 지정하는 데 사용할 수 있습니다.
	예를 들어, 'blob:limit=1k'는 'blob:limit=1024'와 동일합니다.
+
'--filter=object:type=(tag|commit|tree|blob)' 형태는 요청된 유형이 아닌 모든 객체를 생략합니다.

--path=<path>::
	`--textconv` 또는 `--filters`와 함께 사용되어 객체 이름과 경로를 별도로 지정할 수 있도록 합니다.
	예를 들어, blob이 어느 리비전에서 왔는지 추정하기 어려운 경우에 사용합니다.

--batch::
--batch=<format>::
	표준 입력으로 제공된 각 객체에 대한 객체 정보 및 내용을 출력합니다.
	`--textconv`, `--filters`, 또는 `--use-mailmap`을 제외한 다른 옵션이나 인자와 함께 사용할 수 없습니다.
+
--
	* `--textconv` 또는 `--filters`와 함께 사용될 때, 입력 줄은
	  공백으로 구분된 경로를 지정해야 합니다. 자세한 내용은 아래
	  `BATCH OUTPUT` 섹션을 참조하십시오.

	* `--use-mailmap`과 함께 사용될 때, 커밋 및 태그 객체의 경우,
	  출력의 내용 부분은 메일맵 메커니즘을 사용하여 대체된 사용자 정보를 표시하고,
	  정보 부분은 실제 식별자를 대체한 것처럼 객체의 크기를 표시합니다.
--

--batch-check::
--batch-check=<format>::
	표준 입력으로 제공된 각 객체에 대한 객체 정보를 출력합니다.
	`--textconv`, `--filters` 또는 `--use-mailmap`을 제외한 다른 옵션이나 인자와 함께 사용할 수 없습니다.
+
--
	* `--textconv` 또는 `--filters`와 함께 사용될 때, 입력 줄은
	  공백으로 구분된 경로를 지정해야 합니다. 자세한 내용은 아래
	  `BATCH OUTPUT` 섹션을 참조하십시오.

	* `--use-mailmap`과 함께 사용될 때, 커밋 및 태그 객체의 경우,
	  출력되는 객체 정보는 해당 객체에 기록된 식별자가 메일맵 메커니즘으로
	  대체된 것처럼 객체의 크기를 표시합니다.
--

--batch-command::
--batch-command=<format>::
	명령과 인수를 표준 입력에서 읽는 명령 모드로 진입합니다.
	`--buffer`, `--textconv`, `--use-mailmap` 또는 `--filters`와만 결합될 수 있습니다.
+
--
	* `--textconv` 또는 `--filters`와 함께 사용될 때, 입력 줄은
	  공백으로 구분된 경로를 지정해야 합니다. 자세한 내용은 아래
	  `BATCH OUTPUT` 섹션을 참조하십시오.

	* `--use-mailmap`과 함께 사용될 때, 커밋 및 태그 객체의 경우,
	  `contents` 명령은 메일맵 메커니즘을 사용하여 대체된 사용자 정보를 표시하고,
	  `info` 명령은 실제 식별자를 대체한 것처럼 객체의 크기를 표시합니다.
--
+
`--batch-command`는 다음 명령을 인식합니다:
+
--
contents <object>::
	객체 참조 `<object>`의 객체 내용을 출력합니다. 이는 `--batch`의 출력과 일치합니다.

info <object>::
	객체 참조 `<object>`의 객체 정보를 출력합니다. 이는 `--batch-check`의 출력과 일치합니다.

flush::
	`--buffer`와 함께 사용하여 시작 이후 또는 마지막 flush 이후에 발행된 모든 명령을 실행합니다.
	`--buffer`를 사용하면 `flush`가 발행될 때까지 출력이 나오지 않습니다.
	`--buffer`를 사용하지 않으면 `flush`를 발행하지 않고 매번 명령이 flush됩니다.
--
+

--batch-all-objects::
	표준 입력에서 객체 목록을 읽는 대신,
	저장소 내의 모든 객체 및 대체 객체 저장소 (연결된 객체만 해당되지 않음)에 대해
	요청된 배치 작업을 수행합니다.
	`--batch` 또는 `--batch-check`가 지정되어야 합니다. 기본적으로,
	객체는 해시로 정렬된 순서로 방문됩니다; 아래의 `--unordered`도 참조하십시오.
	객체는 linkgit:git-replace[1]의 "replace" 메커니즘을 존중하지 않고 그대로 표시됩니다.

--buffer::
	일반적으로 배치 출력은 각 객체가 출력된 후 flush되므로,
	프로세스가 대화식으로 `cat-file`에서 읽고 쓸 수 있습니다.
	이 옵션을 사용하면 출력은 일반 stdio 버퍼링을 사용합니다;
	이는 많은 수의 객체에 대해 `--batch-check` 또는 `--batch-command`를 호출할 때
	훨씬 더 효율적입니다.

--unordered::
	`--batch-all-objects`가 사용될 때, 객체 해시 순서보다
	효율적인 객체 접근 순서로 객체를 방문합니다.
	순서의 정확한 세부 사항은 명시되지 않았지만, 특정 순서가 필요하지 않은 경우,
	특히 `--batch`와 함께 사용할 때 더 빠른 출력을 제공해야 합니다.
	`cat-file`은 저장소에 여러 번 저장된 경우에도 각 객체를 한 번만 표시합니다.

--follow-symlinks::
	`--batch` 또는 `--batch-check`와 함께,
	tree-ish:path-in-tree 형태의 확장 SHA-1 표현식을 사용하여
	저장소 내의 심볼릭 링크를 따라갑니다.
	링크 자체에 대한 정보를 제공하는 대신, 링크된 객체에 대한 정보를 제공합니다.
	심볼릭 링크가 tree-ish 외부를 가리키는 경우 (예: `/foo`로의 링크 또는 `../foo`로의 루트 레벨 링크),
	트리 외부의 링크 부분은 출력됩니다.
+
이 옵션은 (현재) 인덱스의 객체가 지정된 경우 (예: `HEAD:link` 대신 `:link`)
	트리의 객체가 아닌 경우 올바르게 작동하지 않습니다.
+
이 옵션은 `--batch` 또는 `--batch-check`가 사용되지 않는 한 (현재) 사용할 수 없습니다.
+
예를 들어, git 저장소에 다음이 포함되어 있다고 가정해 봅시다:
+
--
	f: "hello\n"을 포함하는 파일
	link: f를 가리키는 심볼릭 링크
	dir/link: ../f를 가리키는 심볼릭 링크
	plink: ../f를 가리키는 심볼릭 링크
	alink: /etc/passwd를 가리키는 심볼릭 링크
--
+
일반 파일 `f`의 경우, `echo HEAD:f | git cat-file --batch`는 다음을 출력합니다:
+
--
	ce013625030ba8dba906f756967f9e9ca394464a blob 6
--
+
그리고 `echo HEAD:link | git cat-file --batch --follow-symlinks`는
	`HEAD:f`를 가리키므로 동일한 것을 출력합니다. `HEAD:dir/link`도 마찬가지입니다.
+
`--follow-symlinks` 없이, 이것들은 심볼릭 링크 자체에 대한 데이터를 출력합니다.
	`HEAD:link`의 경우, 다음을 볼 수 있습니다:
+
--
	4d1ae35ba2c8ec712fa2a379db44ad639ca277bd blob 1
--
+
`plink`와 `alink` 모두 트리 외부를 가리키므로 각각 다음을 출력합니다:
+
--
	symlink 4
	../f

	symlink 11
	/etc/passwd
--

-Z::
	`--batch`, `--batch-check`, 또는 `--batch-command`와 함께 의미가 있습니다;
	입력 및 출력은 줄 끝 문자 대신 NUL 문자로 구분됩니다.

-z::
	`--batch`, `--batch-check`, 또는 `--batch-command`와 함께 의미가 있습니다;
	입력은 줄 끝 문자 대신 NUL 문자로 구분됩니다. 이 옵션은
	출력이 모호해질 수 있으므로 `-Z`에 비해 사용되지 않습니다.


OUTPUT
------
`-t`가 지정되면, `<type>` 중 하나입니다.

`-s`가 지정되면, `<object>`의 크기 (바이트)입니다.

`-e`가 지정되면, 출력은 없으며 `<object>`가 손상된 경우를 제외하고는 마찬가지입니다.

`-p`가 지정되면, `<object>`의 내용이 보기 좋게 출력됩니다.

`<type>`이 지정되면, `<object>`의 원시 (압축되지 않은) 내용이 반환됩니다.

BATCH OUTPUT
------------

`--batch` 또는 `--batch-check`가 주어지면, `cat-file`은 표준 입력에서 객체를
한 줄에 하나씩 읽고, 읽은 순서대로 객체에 대한 정보를 출력합니다. 기본적으로,
전체 줄이 객체로 간주되며, linkgit:git-rev-parse[1]에 전달된 것처럼 처리됩니다.

`--batch-command`가 주어지면, `cat-file`은 표준 입력에서 명령을 한 줄에 하나씩 읽고,
지정된 명령에 기반한 정보를 출력합니다. `--batch-command`와 함께,
`info` 명령 다음에 객체가 오면 `--batch-check`와 동일한 방식으로 객체에 대한 정보를 출력하고,
`contents` 명령 다음에 객체가 오면 `--batch`와 동일한 방식으로 내용을 출력합니다.

사용자 지정 `<format>`을 사용하여 각 객체에 대해 표시할 정보를 지정할 수 있습니다.
`<format>`은 각 객체에 대해 표준 출력으로 문자 그대로 복사되며, `%(atom)` 형식의 자리 표시자가 확장된 후 줄 끝 문자가 붙습니다. 사용 가능한 원자는 다음과 같습니다:

`objectname`::
	객체 이름의 전체 16진수 표현입니다.

`objecttype`::
	객체의 유형 (cat-file -t가 보고하는 것과 동일).

`objectmode`::
	지정된 객체가 모드 정보를 가지고 있는 경우 (예: 트리 또는 인덱스 항목),
	8진수 정수로 표현된 모드입니다. 그렇지 않으면 빈 문자열입니다.

`objectsize`::
	객체의 크기 (바이트). (cat-file -s가 보고하는 것과 동일).

`objectsize:disk`::
	객체가 디스크에 차지하는 크기 (바이트). 아래 `CAVEATS` 섹션의
	디스크 사용량에 대한 참고 사항을 참조하십시오.

`deltabase`::
	객체가 디스크에서 델타로 저장된 경우, 델타 기반 객체 이름의
	전체 16진수 표현으로 확장됩니다.
	그렇지 않으면 널 OID (모든 0)로 확장됩니다. 아래 `CAVEATS`를 참조하십시오.

`rest`::
	이 원자가 출력 문자열에 사용된 경우, 입력 줄은 첫 번째 공백 경계에서 분할됩니다.
	그 공백 이전의 모든 문자는 객체 이름으로 간주됩니다; 첫 번째 공백 실행 후의 문자 (즉, 줄의 "나머지")는
	`%(rest)` 원자 대신 출력됩니다.

포맷이 지정되지 않으면, 기본 포맷은 `%(objectname) %(objecttype) %(objectsize)`입니다.

`--batch`가 지정되거나, `contents` 명령과 함께 `--batch-command`가 사용되면,
객체 정보 뒤에 객체 내용 ( `%(objectsize)` 바이트로 구성)이 오고,
그 뒤에 줄 끝 문자가 붙습니다.

예시: 사용자 지정 포맷이 없는 `--batch`는 다음을 생성합니다:

-----------
<oid> SP <type> SP <size> LF
<contents> LF
-----------

반면 `--batch-check='%(objectname) %(objecttype)'`는 다음을 생성합니다:

------------
<oid> SP <type> LF
------------

표준 입력에 지정된 이름이 저장소의 객체로 해석될 수 없는 경우,
`cat-file`은 사용자 지정 포맷을 무시하고 다음을 출력합니다:

------------
<object> SP missing LF
------------

표준 입력에 지정된 이름이 `--filter=`를 통해 필터링된 경우,
`cat-file`은 사용자 지정 포맷을 무시하고 다음을 출력합니다:

------------
<object> SP excluded LF
------------

확실하지 않은 짧은 SHA (여러 객체를 가리킬 수 있는 이름)가 지정된 경우,
`cat-file`은 사용자 지정 포맷을 무시하고 다음을 출력합니다:

------------
<object> SP ambiguous LF
------------

트리 내의 서브모듈 항목을 가리킬 수 있고 대상 객체가 저장소에 존재하지 않는 이름이 지정된 경우,
`cat-file`은 사용자 지정 포맷을 무시하고 다음을 출력합니다 (서브모듈의 객체 ID와 함께):

------------
<oid> SP submodule LF
------------

`--follow-symlinks`가 사용되고 저장소 내의 심볼릭 링크가 저장소 외부를 가리키는 경우,
`cat-file`은 사용자 지정 포맷을 무시하고 다음을 출력합니다:

------------
symlink SP <size> LF
<symlink> LF
------------

심볼릭 링크는 절대 경로 ( `/`로 시작)이거나 트리 루트에 상대적인 경로입니다.
예를 들어, dir/link가 `../../foo`를 가리키면 `<symlink>`는 `../foo`가 됩니다.
`<size>`는 심볼릭 링크의 크기 (바이트)입니다.

`--follow-symlinks`가 사용될 때, 다음 오류 메시지가 표시됩니다:

------------
<object> SP missing LF
------------
초기 심볼릭 링크가 존재하지 않을 때 출력됩니다.

------------
dangling SP <size> LF
<object> LF
------------
초기 심볼릭 링크는 존재하지만,
그것이 (간접적으로) 가리키는 어떤 것이 존재하지 않을 때 출력됩니다.

------------
loop SP <size> LF
<object> LF
------------
심볼릭 링크 루프 (또는 40회 이상의 링크 확인이 필요한 심볼릭 링크)에 대해 출력됩니다.

------------
notdir SP <size> LF
<object> LF
------------
심볼릭 링크 확인 중에 디렉터리 이름으로 파일이 사용될 때 출력됩니다.

대안으로, `-Z`가 전달되면, 위의 예시에서 줄 끝 문자가 NUL 문자로 대체됩니다.
이는 출력 자체에 줄 바꿈 문자를 포함할 경우 출력이 분석 가능하도록 보장하며,
스크립팅 목적으로 권장됩니다.

CAVEATS
-------

디스크 상 객체의 크기는 정확하게 보고되지만,
어떤 ref 또는 객체가 디스크 사용량의 원인인지 결론을 도출할 때는 주의해야 합니다.
팩된 비 델타 객체의 크기는 그것에 대해 델타화되는 객체의 크기보다 훨씬 클 수 있지만,
어떤 객체를 기반으로 하고 어떤 객체를 델타로 할지 선택하는 것은 임의적이며
repack 중에 변경될 수 있습니다.

또한 객체 데이터베이스에 객체의 여러 복사본이 존재할 수 있음에 유의하십시오;
이 경우, 어떤 복사본의 크기 또는 델타 기반이 보고될지는 정의되지 않습니다.
