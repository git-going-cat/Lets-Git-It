git-ls-files(1)
===============

NAME
----
git-ls-files - 인덱스와 워킹 트리의 파일 정보 표시


SYNOPSIS
--------
[verse]
'git ls-files' [-z] [-t] [-v] [-f]
		[-c|--cached] [-d|--deleted] [-o|--others] [-i|--ignored]
		[-s|--stage] [-u|--unmerged] [-k|--killed] [-m|--modified]
		[--resolve-undo]
		[--directory [--no-empty-directory]] [--eol]
		[--deduplicate]
		[-x <pattern>|--exclude=<pattern>]
		[-X <file>|--exclude-from=<file>]
		[--exclude-per-directory=<file>]
		[--exclude-standard]
		[--error-unmatch] [--with-tree=<tree-ish>]
		[--full-name] [--recurse-submodules]
		[--abbrev[=<n>]] [--format=<format>] [--] [<file>...]

DESCRIPTION
-----------
이 명령은 인덱스의 파일 목록과 실제 워킹 디렉토리 목록을 병합하여
다양한 조합을 보여줍니다.

어떤 파일이 표시되는지 결정하기 위해 여러 플래그를 사용할 수 있으며,
인덱스에 여러 항목이 있거나 관련 파일 선택 옵션에 여러 상태가 적용될 수
있는 경우 각 파일이 여러 번 출력될 수 있습니다.

OPTIONS
-------
-c::
--cached::
	Git의 인덱스에 캐시된 모든 파일, 즉 추적된 모든 파일을 표시합니다.
	(기본값은 -c/-s/-d/-o/-u/-k/-m/--resolve-undo 옵션이 지정되지 않은
	경우입니다.)

-d::
--deleted::
	스테이지에 적용되지 않은 삭제가 있는 파일을 표시합니다.

-m::
--modified::
	스테이지에 적용되지 않은 수정이 있는 파일을 표시합니다 (스테이지에
	적용되지 않은 삭제도 스테이지에 적용되지 않은 수정으로 간주됩니다).

-o::
--others::
	출력에서 다른 (즉, 추적되지 않은) 파일을 표시합니다.

-i::
--ignored::
	출력에서 무시된 파일만 표시합니다.
	명시적인 '-c' 또는 '-o'와 함께 사용해야 합니다.
	인덱스의 파일을 표시할 때 ('-c'와 함께 사용 시),
	제외 패턴과 일치하는 파일만 출력합니다.
	"다른" 파일을 표시할 때 ('-o'와 함께 사용 시),
	제외 패턴과 일치하는 파일만 표시합니다.
	표준 제외 규칙은 자동으로 활성화되지 않으므로,
	`--exclude*` 옵션 중 하나 이상이 필요합니다.

-s::
--stage::
	스테이지에 적용된 내용의 모드 비트, 객체 이름 및 스테이지 번호를
	출력에 표시합니다.

--directory::
	전체 디렉토리가 "다른"으로 분류된 경우, 파일 내용을 전부 보여주는
	대신 디렉토리 이름만 (끝에 슬래시 포함) 표시합니다.
	-o/--others 없이 사용하면 효과가 없습니다.

--no-empty-directory::
	빈 디렉토리를 나열하지 않습니다. --directory 없이 사용하면 효과가 없습니다.

-u::
--unmerged::
	병합되지 않은 파일에 대한 정보를 출력에 표시하지만,
	다른 추적된 파일은 표시하지 않습니다 (forced --stage, --cached를
	재정의).

-k::
--killed::
	파일/디렉토리 충돌로 인해 추적된 파일을 파일 시스템에 쓰지 못하게
	되어 제거해야 하는 파일 시스템의 추적되지 않은 파일을 표시합니다.

--resolve-undo::
	인덱스에 resolve-undo 정보가 있는 파일을 해당 resolve-undo
	정보와 함께 표시합니다. (resolve-undo 정보는 "git checkout -m
	$PATH", 즉 실수로 해결된 병합 충돌을 다시 생성하는 데 사용되는
	것입니다.)

-z::
	출력 시 \0 라인 종료 문자를 사용하고 파일 이름을 인용하지 않습니다.
	자세한 내용은 OUTPUT 섹션을 참조하십시오.

--deduplicate::
	파일 이름만 표시할 때, 병합 중 여러 스테이지가 있거나
	`--deleted`와 `--modified` 옵션을 동시에 지정하여 발생할 수 있는
	중복을 억제합니다.
	`-t`, `--unmerged` 또는 `--stage` 옵션 중 하나가 사용 중일 때는
	이 옵션의 효과가 없습니다.

-x <pattern>::
--exclude=<pattern>::
	패턴과 일치하는 추적되지 않은 파일을 건너뜁니다.
	패턴은 쉘 와일드카드 패턴입니다. 자세한 내용은 EXCLUDE PATTERNS
	섹션을 참조하십시오.

-X <file>::
--exclude-from=<file>::
	<file>에서 제외 패턴을 읽습니다. 각 줄에 하나씩 있습니다.

--exclude-per-directory=<file>::
	각 디렉토리와 그 하위 디렉토리에만 적용되는 추가 제외 패턴을
	<file>에서 읽습니다. Porcelain 명령의 작동 방식을 에뮬레이트하려는
	경우, `--exclude-standard` 옵션을 사용하는 것이 더 쉽고 철저합니다.

--exclude-standard::
	표준 Git 제외 규칙을 추가합니다: 각 디렉토리의 .git/info/exclude,
	.gitignore, 그리고 사용자의 전역 제외 파일.

--error-unmatch::
	어떤 <file>이라도 인덱스에 나타나지 않으면 오류로 처리합니다 (1 반환).

--with-tree=<tree-ish>::
	`--error-unmatch`를 사용하여 사용자가 공급한 <file> (즉, 경로 패턴)
	을 경로로 확장할 때, 명명된 <tree-ish> 이후 인덱스에서 제거된
	경로를 아직 존재하는 것으로 가장합니다. 이 옵션을 `-s` 또는 `-u`
	옵션과 함께 사용하는 것은 의미가 없습니다.

-t::
	상태 태그와 함께 파일 이름을 표시합니다.
	스크립팅 목적으로는, linkgit:git-status[1] `--porcelain`과
	linkgit:git-diff-files[1] `--name-status`가 거의 항상 더 나은
	대안입니다. 사용자는 linkgit:git-status[1] `--short` 또는
	linkgit:git-diff[1] `--name-status`를 더 사용자 친화적인 대안으로
	살펴봐야 합니다.
+
--
	이 옵션은 각 파일 이름을 표시하는 이유를 상태 태그 형식으로 제공합니다
	(상태 태그 뒤에 공백과 파일 이름이 옵니다).
	상태 태그는 다음 목록의 단일 문자입니다:

	H::	unmerged 또는 skip-worktree가 아닌 추적된 파일
	S::	skip-worktree인 추적된 파일
	M::	병합되지 않은 추적된 파일
	R::	스테이지에 적용되지 않은 제거/삭제가 있는 추적된 파일
	C::	스테이지에 적용되지 않은 수정/변경이 있는 추적된 파일
	K::	추적된 파일을 체크아웃하는 것을 방해하는 파일/디렉토리 충돌의
		일부인 추적되지 않은 경로
	?::	추적되지 않은 파일
	U::     resolve-undo 정보가 있는 파일
--

-v::
	`-t`와 유사하지만, 'assume unchanged'로 표시된 파일에 대해
	소문자를 사용합니다 (linkgit:git-update-index[1] 참조).

-f::
	`-t`와 유사하지만, 'fsmonitor valid'로 표시된 파일에 대해
	소문자를 사용합니다 (linkgit:git-update-index[1] 참조).

--full-name::
	하위 디렉토리에서 실행될 때, 이 명령은 일반적으로 현재
	디렉토리에 상대적인 경로를 출력합니다. 이 옵션은 경로를
	프로젝트 최상위 디렉토리에 상대적으로 출력하도록 강제합니다.

--recurse-submodules::
	저장소의 각 활성 하위 모듈에 대해 ls-files를 재귀적으로 호출합니다.
	현재 --cached 및 --stage 모드만 지원됩니다.

--abbrev[=<n>]::
	40바이트 16진수 객체 줄 대신, 객체를 고유하게 참조하는 '<n>'
	개의 16진수 숫자로 시작하는 가장 짧은 접두사를 표시합니다.
	--abbrev=<n>으로 기본값이 아닌 자릿수를 지정할 수 있습니다.

--debug::
	파일을 설명하는 각 줄 뒤에 캐시 항목에 대한 추가 데이터를
	추가합니다. 이는 수동 검사를 위해 가능한 많은 정보를 표시하기
	위한 것입니다. 정확한 형식은 언제든지 변경될 수 있습니다.

--eol::
	파일의 <eolinfo>와 <eolattr>를 표시합니다.
	<eolinfo>는 Git이 "text" 속성이 "auto"일 때 (또는 설정되지 않고
	core.autocrlf가 false가 아닐 때) 사용하는 파일 내용 식별자입니다.
	<eolinfo>는 "-text", "none", "lf", "crlf", "mixed" 또는 "" 중 하나입니다.
+
""은 파일이 일반 파일이 아님을 의미합니다. 인덱스에 없거나
워킹 트리에 접근할 수 없음을 의미합니다.
+
<eolattr>는 체크아웃 또는 커밋 시 사용되는 속성이며, "", "-text",
"text", "text=auto", "text eol=lf", "text eol=crlf" 중 하나입니다.
Git 2.10부터 "text=auto eol=lf"와 "text=auto eol=crlf"가 지원됩니다.
+
인덱스의 <eolinfo> ("i/<eolinfo>")와 워킹 트리의 <eolinfo> ("w/<eolinfo>")
모두 일반 파일의 경우 표시되며, 그 뒤에 ("attr/<eolattr>")이 따라옵니다.

--sparse::
	인덱스가 희소(sparse)인 경우, 포함된 파일을 확장하지 않고 희소
	디렉토리만 표시합니다. 희소 디렉토리는 끝에 슬래시가 붙어
	"x/"와 같이 표시됩니다.

--format=<format>::
	표시되는 결과에서 `%(fieldname)`을 보간하는 문자열입니다.
	또한 `%%`를 `%`로, `XX`가 16진수 숫자인 `%xXX`를 16진수 코드
	`XX`를 가진 문자로 보간합니다. 예를 들어 `%x00`은 `\0` (NUL),
	`%x09`는 `\t` (TAB), `%x0a`는 `\n` (LF)으로 보간됩니다.
	--format은 `-s`, `-o`, `-k`, `-t`, `--resolve-undo` 및 `--eol`과
	결합할 수 없습니다.
\--::
	더 이상의 인수를 옵션으로 해석하지 않습니다.

<file>::
	표시할 파일. 파일이 지정되지 않으면 지정된 다른 기준에 맞는
	모든 파일이 표시됩니다.

OUTPUT
------
'git ls-files'는 `--stage`가 지정된 경우가 아니면 파일 이름만 출력합니다.
`--stage`가 지정된 경우 다음과 같이 출력합니다:

        [<tag> ]<mode> <object> <stage> <file>

'git ls-files --eol'은 다음과 같이 표시합니다:
	i/<eolinfo><SPACES>w/<eolinfo><SPACES>attr/<eolattr><SPACE*><TAB><file>

'git ls-files --unmerged'와 'git ls-files --stage'는 병합되지 않은
경로의 자세한 정보를 검사하는 데 사용할 수 있습니다.

병합되지 않은 경로의 경우, 단일 모드/SHA-1 쌍을 기록하는 대신,
인덱스는 최대 세 개의 쌍을 기록합니다. stage 1의 tree O, stage 2의 A,
stage 3의 B에서 나온 각 쌍입니다. 이 정보는 사용자가 (또는 Porcelain이)
해당 경로에 궁극적으로 기록될 것을 보는 데 사용할 수 있습니다. (linkgit:git-read-tree[1]에서 상태에 대한 자세한 내용을 참조하십시오.)

`-z` 옵션이 없으면, "비정상적인" 문자를 포함한 경로 이름은
`core.quotePath` 구성 변수에 설명된 대로 인용됩니다 (linkgit:git-config[1] 참조).
`-z`를 사용하면 파일 이름이 그대로 출력되고 줄은 NUL 바이트로 종료됩니다.

`--format=<format>` 옵션을 사용하여 사용자 정의 형식으로 출력할 수 있으며,
이는 `%(fieldname)` 표기법을 사용하여 다양한 필드를 보간할 수 있습니다.
예를 들어, "objectname" 및 "path" 필드만 필요한 경우 다음 `--format`과
함께 실행할 수 있습니다:

	git ls-files --format='%(objectname) %(path)'

FIELD NAMES
-----------
각 경로가 표시되는 방식은 `--format=<format>` 옵션을 사용하여 사용자 정의할 수
있습니다. 여기서 `<format>` 문자열의 `%(fieldname)`은 인덱스 항목의
다양한 측면을 보간합니다. 다음 "fieldname"이 이해됩니다:

objectmode::
	인덱스에 기록된 파일의 모드입니다.
objecttype::
	인덱스에 기록된 파일의 객체 유형입니다.
objectname::
	인덱스에 기록된 파일의 이름입니다.
objectsize[:padded]::
	인덱스에 기록된 파일의 객체 크기
	("-", 객체가 `commit` 또는 `tree`인 경우).
	"% (objectsize:padded)"와 같이 패딩된 크기 형식도 지원합니다.
stage::
	인덱스에 기록된 파일의 스테이지입니다.
eolinfo:index::
eolinfo:worktree::
	경로에 대해 인덱스 또는 워킹 트리의 <eolinfo> ( `--eol` 옵션 설명 참조)입니다.
eolattr::
	경로에 적용되는 <eolattr> ( `--eol` 옵션 설명 참조)입니다.
path::
	인덱스에 기록된 파일의 경로 이름입니다.

EXCLUDE PATTERNS
----------------

'git ls-files'는 플래그 --others 또는 --ignored가 지정되었을 때
디렉토리 트리를 탐색하고 파일을 찾을 때 "제외 패턴" 목록을 사용할 수 있습니다.
linkgit:gitignore[5]는 제외 패턴의 형식을 지정합니다.

이러한 제외 패턴은 다음 위치에서 순서대로 지정될 수 있습니다:

  1. 명령행 플래그 --exclude=<pattern>은 단일 패턴을 지정합니다.
     패턴은 명령행에 나타나는 순서대로 정렬됩니다.

  2. 명령행 플래그 --exclude-from=<file>은 패턴 목록이 포함된
     파일을 지정합니다. 패턴은 파일에 나타나는 순서대로 정렬됩니다.

  3. 명령행 플래그 --exclude-per-directory=<name>은 'git ls-files'가
     검사하는 각 디렉토리의 파일 이름을 지정합니다. 일반적으로
     `.gitignore`입니다. 더 깊은 디렉토리의 파일이 우선합니다.
     패턴은 파일에 나타나는 순서대로 정렬됩니다.

--exclude 또는 --exclude-from으로 지정된 파일에 읽힌 패턴은
디렉토리 트리의 루트에 상대적입니다. --exclude-per-directory로
지정된 파일에서 읽힌 패턴은 패턴 파일이 나타나는 디렉토리에 상대적입니다.

일반적으로 Porcelain 명령이 적용하는 방식과 동일한 방식으로 제외 규칙을
적용하고 싶을 때 `--exclude-standard`를 사용할 수 있습니다.
`--exclude-standard`가 지정하는 것을 에뮬레이트하려면,
`--exclude-per-directory=.gitignore`를 지정한 다음 다음을 지정하십시오:

  1. `core.excludesfile` 구성 변수에 의해 지정된 파일, 존재하면,
     또는 `$XDG_CONFIG_HOME/git/ignore` 파일.

  2. `$GIT_DIR/info/exclude` 파일.

`--exclude-from=` 옵션을 통해.
