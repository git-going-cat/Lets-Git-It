git-credential-store(1)
=======================

NAME
----
git-credential-store - 디스크에 자격 증명을 저장하는 헬퍼

SYNOPSIS
--------
-------------------
git config credential.helper 'store [<options>]'
-------------------

DESCRIPTION
-----------

NOTE: 이 헬퍼를 사용하면 암호가 암호화되지 않은 상태로 디스크에 저장되며,
파일 시스템 권한으로만 보호됩니다. 이것이 수용할 수 없는 보안 절충이라면,
linkgit:git-credential-cache[1]를 시도하거나 운영 체제에서 제공하는
안전한 저장소와 통합되는 헬퍼를 찾으십시오.

이 명령어는 향후 Git 프로그램에서 사용하기 위해 자격 증명을 디스크에 영구적으로 저장합니다.

아마도 이 명령어를 직접 호출해서는 안 될 것입니다. git의 다른 부분에서
자격 증명 헬퍼로 사용되도록 되어 있습니다. linkgit:gitcredentials[7] 또는
아래 `EXAMPLES`를 참조하십시오.

OPTIONS
-------

--file=<path>::

	`<path>`를 사용하여 자격 증명을 조회하고 저장합니다. 파일은
	시스템의 다른 사용자가 읽을 수 없도록 파일 시스템 권한이 설정되지만,
	암호화되거나 다르게 보호되지는 않습니다. 지정되지 않은 경우,
	`~/.git-credentials` 및 `$XDG_CONFIG_HOME/git/credentials`에서
	자격 증명이 검색되며, `~/.git-credentials`가 존재하는 경우 거기에,
	또는 후자가 존재하지 않고 전자가 존재하는 경우 `$XDG_CONFIG_HOME/git/credentials`에
	자격 증명이 기록됩니다. <<FILES>>도 참조하십시오.

[[FILES]]
FILES
-----

`--file`로 명시적으로 설정되지 않은 경우, git-credential-store가
우선순위에 따라 자격 증명을 검색할 두 개의 파일이 있습니다.

~/.git-credentials::
	사용자별 자격 증명 파일.

$XDG_CONFIG_HOME/git/credentials::
	두 번째 사용자별 자격 증명 파일. '$XDG_CONFIG_HOME'이 설정되지
	않았거나 비어 있는 경우, `$HOME/.config/git/credentials`가 사용됩니다.
	이 파일에 저장된 모든 자격 증명은 `~/.git-credentials`에도
	일치하는 자격 증명이 있는 경우 사용되지 않습니다. 이 파일을 만들지
	않는 것이 좋습니다. 이 파일을 사용하지 않는 구버전 Git이 있는 경우.

자격 증명 조회를 위해 파일은 위의 순서대로 읽히며,
가장 먼저 발견된 일치하는 자격 증명이 목록의 더 뒤에 있는 파일에서
발견된 자격 증명보다 우선합니다.

자격 증명 저장은 기본적으로 목록에서 첫 번째로 존재하는 파일에 기록됩니다.
이러한 파일이 존재하지 않으면 `~/.git-credentials`가 생성되고 기록됩니다.

자격 증명을 삭제할 때, 일치하는 자격 증명은 모든 파일에서 삭제됩니다.

EXAMPLES
--------

이 헬퍼의 요점은 사용자 이름이나 암호를 입력해야 하는 횟수를 줄이는 것입니다. 예를 들어:

------------------------------------------
$ git config credential.helper store
$ git push http://example.com/repo.git
Username: <사용자 이름을 입력하십시오>
Password: <암호를 입력하십시오>

[며칠 후]
$ git push http://example.com/repo.git
[자격 증명이 자동으로 사용됩니다]
------------------------------------------

STORAGE FORMAT
--------------

`.git-credentials` 파일은 일반 텍스트로 저장됩니다. 각 자격 증명은
자체 줄에 다음과 같은 URL 형식으로 저장됩니다:

------------------------------
https://user:pass@example.com
------------------------------

다른 종류의 줄(예: 빈 줄 또는 주석 줄)은
허용되지 않으며, 일부는 암묵적으로 무시될 수도 있습니다.
에디터로 파일을 보거나 편집하지 마십시오.

Git이 특정 URL 컨텍스트에 대한 인증을 필요로 할 때,
credential-store는 해당 컨텍스트를 자격 증명 파일의 각 항목과
일치하는 패턴으로 간주합니다. 프로토콜, 호스트 이름,
및 사용자 이름(이미 있는 경우)이 일치하면, 암호가
Git으로 반환됩니다. 더 자세한 내용은 linkgit:gitcredentials[7]의
구성 토론을 참조하십시오.
