git-send-pack(1)
================

NAME
----
git-send-pack - Git 프로토콜을 통해 다른 저장소로 객체 푸시


SYNOPSIS
--------
[verse]
'git send-pack' [--mirror] [--dry-run] [--force]
		[--receive-pack=<git-receive-pack>]
		[--verbose] [--thin] [--atomic]
		[--[no-]signed | --signed=(true|false|if-asked)]
		[<host>:]<directory> (--all | <ref>...)

DESCRIPTION
-----------
일반적으로 이 명령어의 고수준 래퍼인 'git push'를 사용하는 것이 좋습니다. linkgit:git-push[1]을 참조하십시오.

현재 저장소에서 객체를 보내 명명된 ref를 업데이트하기 위해, 가능한 원격 저장소에서 'git-receive-pack'을 호출합니다.


OPTIONS
-------
--receive-pack=<git-receive-pack>::
	원격지의 'git-receive-pack' 프로그램 경로.
	ssh를 통해 원격 저장소로 푸시할 때 유용할 수 있으며, 기본 $PATH 디렉토리에 해당 프로그램이 없는 경우입니다.

--exec=<git-receive-pack>::
	--receive-pack=<git-receive-pack>과 동일합니다.

--all::
	업데이트할 ref를 명시적으로 지정하는 대신, 로컬에 존재하는 모든 head를 업데이트합니다.

--stdin::
	한 줄에 하나씩 stdin에서 ref 목록을 가져옵니다. 이 옵션 외에 명령줄에 ref가 지정된 경우, stdin의 ref는 명령줄의 ref 뒤에 처리됩니다.
+
`--stateless-rpc`가 이 옵션과 함께 지정된 경우 ref 목록은 패킷 형식(pkt-line)이어야 합니다. 각 ref는 별도의 패킷에 있어야 하며, 목록은 flush 패킷으로 끝나야 합니다.

--dry-run::
	실제로 업데이트를 보내는 것을 제외한 모든 작업을 수행합니다.

--force::
	일반적으로 이 명령어는 덮어쓰려는 로컬 ref의 조상이 아닌 원격 ref를 업데이트하는 것을 거부합니다. 이 플래그는 해당 검사를 비활성화합니다. 이는 원격 저장소에서 커밋이 손실될 수 있음을 의미하므로 주의해서 사용해야 합니다.

--verbose::
	상세 모드로 실행합니다.

--thin::
	"thin" 팩을 보냅니다. 이는 네트워크 트래픽을 줄이기 위해 팩에 포함되지 않은 객체를 기준으로 델타 형식으로 객체를 기록합니다.

--atomic::
	ref 업데이트를 위해 트랜잭션을 원자적으로 사용합니다. ref 중 하나라도 업데이트에 실패하면 전체 푸시는 아무런 ref도 변경하지 않고 실패합니다.

--signed::
--no-signed::
--signed=(true|false|if-asked)::
	GPG로 푸시 요청에 서명하여 수신 측에서 ref를 업데이트하도록 합니다. 이를 통해 훅에서 검사하거나 로그로 기록할 수 있습니다. `false` 또는 `--no-signed`이면 서명이 시도되지 않습니다. `true` 또는 `--signed`이면 서버가 서명된 푸시를 지원하지 않는 경우 푸시가 실패합니다. `if-asked`로 설정하면 서버가 서명된 푸시를 지원하는 경우에만 서명합니다. `gpg --sign` 호출이 실패해도 푸시는 실패합니다. 수신 측에서의 자세한 내용은 linkgit:git-receive-pack[1]을 참조하십시오.

--push-option=<string>::
	지정된 문자열을 푸시 옵션으로 전달하여 서버 측 훅에서 소비하도록 합니다. 서버가 푸시 옵션을 지원하지 않으면 오류가 발생합니다. 자세한 내용은 linkgit:git-push[1] 및 linkgit:githooks[5]를 참조하십시오.

<host>::
	저장소를 호스팅할 원격 호스트입니다. 이 부분이 지정되면 'git-receive-pack'은 ssh를 통해 호출됩니다.

<directory>::
	업데이트할 저장소입니다.

<ref>...::
	업데이트할 원격 ref입니다.


SPECIFYING THE REFS
-------------------

원격지에서 업데이트할 ref를 지정하는 세 가지 방법이 있습니다.

`--all` 플래그를 사용하면 로컬에 존재하는 모든 ref가 원격지로 전송됩니다. 이 플래그를 사용하면 '<ref>'를 지정할 수 없습니다.

`--all` 없이 '<ref>' 없이 사용하면 로컬 측과 원격 측 모두에 존재하는 head가 업데이트됩니다.

하나 이상의 '<ref>'가 명시적으로 지정될 때 (명령줄이든 `--stdin`을 통하든), 단일 패턴이거나 콜론 ":"으로 분리된 두 개의 패턴 쌍일 수 있습니다 (이는 ref 이름에 콜론이 포함될 수 없음을 의미). 단일 패턴 '<name>'은 단순히 '<name>:<name>'의 약식입니다.

각 패턴 쌍은 소스 측(콜론 앞)과 대상 측(콜론 뒤)으로 구성됩니다. 푸시될 ref는 소스 측과 일치하는 것을 찾아 결정되며, 푸시되는 위치는 대상 측을 사용하여 결정됩니다. ref를 일치시키는 데 사용되는 규칙은 'git rev-parse'가 심볼릭 ref 이름을 해석하는 데 사용하는 규칙과 동일합니다. linkgit:git-rev-parse[1]을 참조하십시오.

 - `<src>`가 로컬 ref 중 정확히 하나와 일치하지 않으면 오류입니다.

 - `<dst>`가 두 개 이상의 원격 ref와 일치하면 오류입니다.

 - `<dst>`가 어떤 원격 ref와도 일치하지 않으면,

   * "refs/"로 시작해야 합니다. 이 경우 `<dst>`는 대상으로 문자 그대로 사용됩니다.

   * `<src>` == `<dst>`이고 `<src>`와 일치하는 ref가 원격 ref 집합에 존재하지 않아야 합니다. 이 경우 로컬에서 `<src>`와 일치한 ref가 대상 이름으로 사용됩니다.

`--force` 없이 `<src>` ref는 `<dst>`가 존재하지 않거나 `<dst>`가 `<src>`의 올바른 부분 집합 (즉, 조상)인 경우에만 원격지에 저장됩니다. "fast-forward check"라고 하는 이 검사는 원격 ref를 실수로 덮어쓰고 다른 사람의 커밋을 잃는 것을 방지하기 위해 수행됩니다.

`--force`를 사용하면 모든 ref에 대해 fast-forward check가 비활성화됩니다.

선택적으로, `<ref>` 매개변수에 '+' 기호를 접두사로 붙여 해당 ref에 대해서만 fast-forward check를 비활성화할 수 있습니다.
