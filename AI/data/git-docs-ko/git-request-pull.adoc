git-request-pull(1)
===================

NAME
----
git-request-pull - 보류 중인 변경 사항 요약 생성

SYNOPSIS
--------
[verse]
'git request-pull' [-p] <start> <URL> [<end>]

DESCRIPTION
-----------

상류 프로젝트에 변경 사항을 pull하도록 요청하는 요청을 생성합니다.
표준 출력으로 인쇄되는 요청은 브랜치 설명으로 시작하고,
변경 사항을 요약하며, 어디에서 pull할 수 있는지 나타냅니다.

상류 프로젝트는 `<start>`로 명명된 커밋을 가지고 있다고 가정하며,
출력은 해당 커밋 이후에 사용자가 만든 변경 사항을 `<end>`로 명명된 커밋까지
`<URL>`로 명명된 저장소를 방문하여 통합하도록 요청합니다.


OPTIONS
-------
-p::
	출력에 패치 텍스트를 포함합니다.

<start>::
	시작할 커밋입니다. 이미 상류 히스토리에 있는 커밋을 가리킵니다.

<URL>::
	pull할 저장소 URL입니다.

<end>::
	끝낼 커밋입니다 (기본값은 HEAD). pull하도록 요청하는 히스토리의
	최상단 커밋을 가리킵니다.
+
`<URL>`로 명명된 저장소에 로컬의 ref와 다른 ref의 최상단에 커밋이 있는 경우,
`<local>:<remote>` 구문을 사용하여 해당 로컬 이름, 콜론 `:`, 그리고
해당 원격 이름을 지정할 수 있습니다.


EXAMPLES
--------

`master` 브랜치에서 `v1.0` 릴리스 위에 작업을 구축했으며,
이를 프로젝트에 통합하고 싶다고 가정해 봅시다.
먼저 해당 변경 사항을 다른 사람이 볼 수 있도록 공개 저장소에 push합니다:

	git push https://git.ko.xz/project master

그런 다음 이 명령을 실행합니다:

	git request-pull v1.0 https://git.ko.xz/project master

이것은 `v1.0` 릴리스와 사용자의 `master` 사이의 변경 사항을 요약하고,
공개 저장소에서 pull하도록 상류에 요청을 생성합니다.

이 변경 사항을 로컬에 있는 브랜치의 이름과 다른 브랜치에 push한 경우, 예를 들어:

	git push https://git.ko.xz/project master:for-linus

그러면 다음과 같이 pull하도록 요청할 수 있습니다:

	git request-pull v1.0 https://git.ko.xz/project master:for-linus
