git-bugreport(1)
================

NAME
----
git-bugreport - 사용자에게 버그 리포트 제출 정보를 수집합니다

SYNOPSIS
--------
[verse]
'git bugreport' [(-o | --output-directory) <path>]
		[(-s | --suffix) <format> | --no-suffix]
		[--diagnose[=<mode>]]

DESCRIPTION
-----------
사용자의 머신, Git 클라이언트, 저장소 상태에 대한 정보를 수집하고, 사용자가 관찰한 동작에 대한 정보를 요청하는 양식과 함께 단일 텍스트 파일에 저장합니다. 이 파일은 예를 들어 Git 메일링 리스트와 같이 공유하여 관찰된 버그를 보고할 수 있도록 합니다.

사용자에게 다음과 같은 정보가 요청됩니다:

 - 재현 단계 (Reproduction steps)
 - 예상 동작 (Expected behavior)
 - 실제 동작 (Actual behavior)

다음 정보는 자동으로 캡처됩니다:

 - 'git version --build-options'
 - uname sysname, release, version, 및 machine 문자열
 - 컴파일러별 정보 문자열 (Compiler-specific info string)
 - 활성화된 훅 목록 (A list of enabled hooks)
 - $SHELL

추가적인 정보는 `--diagnose` 옵션을 사용하여 별도의 zip 아카이브에 수집될 수 있으며, 버그리포트 문서와 함께 첨부되어 독자들에게 추가적인 문맥을 제공할 수 있습니다.

이 도구는 일반적인 Git 설정 프로세스를 통해 호출되며, 경우에 따라서는 - 예를 들어 관련 설정 파일을 읽을 수 없는 경우 - 실행되지 않을 수도 있습니다. 이러한 시나리오에서는 도움을 요청할 때 위에 나열된 종류의 정보를 수동으로 수집하는 것이 도움이 될 수 있습니다.

OPTIONS
-------
-o <path>::
--output-directory <path>::
	결과 버그 리포트 파일을 현재 디렉토리 대신 `<path>`에 저장합니다.

-s <format>::
--suffix <format>::
--no-suffix::
	버그리포트 이름에 대한 대체 접미사를 지정하여 'git-bugreport-<formatted-suffix>'라는 이름의 파일을 생성합니다. 이는 strftime(3) 형식 문자열 형태를 취해야 하며, 현재 로컬 시간이 사용됩니다.
	`--no-suffix`는 접미사를 비활성화하며 파일은 구별하기 위한 조치 없이 단순히 `git-bugreport`로 명명됩니다.

--no-diagnose::
--diagnose[=<mode>]::
	사용자의 머신, Git 클라이언트, 저장소 상태에 대한 보충 정보의 zip 아카이브를 생성합니다. 아카이브는 버그 리포트와 동일한 출력 디렉토리에 기록되며 'git-diagnostics-<formatted-suffix>'로 명명됩니다.
+
`mode`가 지정되지 않으면, 진단 아카이브는 `git diagnose`에서 보고하는 기본 통계 세트를 포함합니다. 선택적인 `mode` 값을 지정하여 아카이브에 포함될 정보를 변경할 수 있습니다. `mode`의 유효한 값 목록과 사용 방법에 대한 자세한 내용은 linkgit:git-diagnose[1]를 참조하십시오.
