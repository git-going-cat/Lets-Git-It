> 각 서비스에서 발급받은 키/시크릿 값은 해당 컴포넌트의 `.env` 파일에 입력합니다.

## 1. Google Cloud — OAuth2 소셜 로그인

### 용도
- 구글 계정으로 소셜 로그인 (Spring Security OAuth2 Client)
- 권한 스코프: `email`, `profile`

### 가입 및 설정 방법

1. [Google Cloud Console](https://console.cloud.google.com) 접속 → 프로젝트 생성
2. **API 및 서비스 → 사용자 인증 정보** 메뉴 진입
3. **OAuth 2.0 클라이언트 ID 만들기** 선택
   - 애플리케이션 유형: `웹 애플리케이션`
   - 승인된 리디렉션 URI 추가:
     - 개발: `http://localhost:8080/login/oauth2/code/google`
     - 운영: `https://api.lets-git-it.kr/login/oauth2/code/google`
4. 클라이언트 ID와 클라이언트 시크릿 발급

### 환경 변수 설정 (`BE/letsgitit/.env`)

```
GOOGLE_CLIENT_ID=<클라이언트 ID>
GOOGLE_CLIENT_SECRET=<클라이언트 시크릿>
FRONTEND_REDIRECT_URI=https://lets-git-it.kr/auth/callback/google
OAUTH2_COOKIE_SECURE=true   # HTTPS 환경에서 true
```

> OAuth2 동의 화면(OAuth consent screen)에서 앱 정보 및 테스트 사용자를 등록해야 합니다.  
> 외부 공개 전까지는 **테스트 모드**로 운영하고, 출시 시 **프로덕션** 전환 필요.

## 2. Gmail SMTP — 이메일 발송

### 용도
- 회원가입 인증 메일, 비밀번호 재설정 등 트랜잭션 이메일 발송
- SMTP 서버: `smtp.gmail.com:587` (STARTTLS)

### 가입 및 설정 방법

1. 발신에 사용할 Gmail 계정 준비
2. Google 계정 → **보안** → **2단계 인증** 활성화 (필수)
3. **앱 비밀번호** 생성:
   - 구글 계정 → 보안 → 2단계 인증 → **앱 비밀번호**
   - 앱: `기타(직접 입력)`, 이름: `letsgitit`
   - 16자리 앱 비밀번호 복사

### 환경 변수 설정 (`BE/letsgitit/.env`)

```
MAIL_USERNAME=<Gmail 주소>       # 예: letsgitit@gmail.com
MAIL_PASSWORD=<16자리 앱 비밀번호>
```

> 계정 비밀번호가 아닌 **앱 비밀번호**를 사용해야 합니다.

## 3. OpenRouter — AI LLM 및 임베딩

### 용도
- Pro Git 2판 기반 RAG(Retrieval-Augmented Generation) API
- LLM 채팅: `google/gemini-2.5-flash-lite` (fallback: `openai/gpt-4o-mini`)
- 임베딩 생성: `openai/text-embedding-3-small`

### 가입 및 설정 방법

1. [OpenRouter](https://openrouter.ai) 회원가입
2. **Keys** 메뉴 → **Create Key** → API 키 발급
3. 크레딧 충전 (LLM 호출 비용 발생)

### 환경 변수 설정 (`AI/.env`)

```
OPENROUTER_API_KEY=<발급받은 API 키>
REDIS_URL=redis://redis-ai:6382
CORS_ORIGINS=https://lets-git-it.kr
AI_API_KEY=<AI 서버 내부 인증용 키 (임의 문자열)>
RATE_LIMIT_PER_MINUTE=30
```

> `AI_API_KEY`는 OpenRouter와 무관하며, AI 서버 엔드포인트를 보호하는 자체 API Key입니다. 임의 문자열로 직접 설정합니다.

### 사용 모델 목록

| 용도 | 모델 ID |
|------|--------|
| 채팅 (메인) | `google/gemini-2.5-flash-lite` |
| 채팅 (fallback) | `openai/gpt-4o-mini` |
| 임베딩 | `openai/text-embedding-3-small` |

## 4. AWS — 서버 인프라

### 용도
- 개발계/운영계 서버 운영

### 서버 구성

| 환경 | 서비스 | 사양 |
|------|--------|------|
| 개발계 | AWS Lightsail | xlarge (4 vCPU / 8 GB) |
| 운영계 | AWS EC2 | m5.xlarge (4 vCPU / 16 GB) |

### 가입 및 설정 방법

1. [AWS Console](https://aws.amazon.com) 계정 생성
2. 서버 생성 후 Ubuntu 24.04 LTS 설치
3. 보안 그룹 인바운드 규칙 설정:
   - `22` (SSH)
   - `80` (HTTP)
   - `443` (HTTPS)
4. SSH 키 페어 생성 및 보관
5. 서버 접속 후 Docker Engine + Docker Compose V2 설치

### GitLab Runner 등록

```bash
# Runner 컨테이너 실행
cd INFRA
docker compose -f docker-compose.runner.yml up -d

# GitLab Runner 등록 (GitLab 프로젝트 설정에서 토큰 확인 필요)
docker exec -it gitlab-runner gitlab-runner register
```

등록 시 입력값:
- GitLab URL: `https://lab.ssafy.com` (또는 사내 GitLab URL)
- Registration Token: GitLab 프로젝트 → Settings → CI/CD → Runners
- Tag: 개발계는 `dev`, 운영계는 `prod`
- Executor: `docker`
- Default Docker image: `docker:latest`

## 5. Let's Encrypt (Certbot) — SSL/TLS 인증서

### 용도
- HTTPS 인증서 발급 및 자동 갱신
- Nginx 컨테이너에 인증서 마운트 (`/etc/letsencrypt`)

### 설치 및 발급 방법

```bash
# 서버에 Certbot 설치 (Ubuntu 24.04)
sudo apt update
sudo apt install certbot

# 인증서 발급 (도메인 소유 확인)
sudo certbot certonly --standalone -d lets-git-it.kr -d api.lets-git-it.kr -d ai.lets-git-it.kr

# 개발계
sudo certbot certonly --standalone -d dev.lets-git-it.kr -d api-dev.lets-git-it.kr -d ai-dev.lets-git-it.kr
```

### 환경 변수 설정 (`INFRA/.env.nginx`)

```
# 운영계
SSL_CERT=/etc/letsencrypt/live/lets-git-it.kr/fullchain.pem
SSL_KEY=/etc/letsencrypt/live/lets-git-it.kr/privkey.pem

# 개발계
SSL_CERT=/etc/letsencrypt/live/dev.lets-git-it.kr/fullchain.pem
SSL_KEY=/etc/letsencrypt/live/dev.lets-git-it.kr/privkey.pem
```

> 인증서 유효 기간은 90일이며, Certbot 자동 갱신 타이머(`certbot renew`)가 설정되어 있어야 합니다.  
> `crontab -e`에 다음 등록 권장: `0 3 * * * certbot renew --quiet`

## 6. GitLab — 소스 저장소 및 CI/CD

### 용도
- 소스코드 저장 및 버전 관리
- MR(Merge Request) 시 자동 테스트
- `develop`/`prod` 브랜치 push 시 자동 배포

### 설정 방법

1. GitLab 프로젝트에서 **Settings → CI/CD → Variables** 등록 필요 시 추가
2. Runner 등록 (4번 AWS 섹션 참고)
3. `.gitlab-ci.yml` 파이프라인은 저장소에 포함되어 자동 실행됨

### 브랜치 전략

| 브랜치 | 목적 |
|--------|------|
| `master` | 기준 브랜치 |
| `develop` | 개발 통합 브랜치 → 개발계 자동 배포 |
| `prod` | 운영 배포 브랜치 → 운영계 자동 배포 |
| `feat/*`, `fix/*` 등 | 기능 개발 브랜치 |

## 7. PostHog — 사용자 행동 분석 (선택)

### 용도
- 게임 이벤트 추적 (게임 시작/종료/포기, 튜토리얼 진행 등)
- 페이지뷰 자동 수집

### 가입 및 설정 방법

1. [PostHog](https://posthog.com) 회원가입 (Cloud 무료 티어 사용 가능)
2. 프로젝트 생성
3. **Project Settings** → **Project API Key** 복사
4. PostHog 호스트 확인 (Cloud: `https://us.i.posthog.com`)

### 환경 변수 설정 (`FE/.env`)

```
VITE_PUBLIC_POSTHOG_KEY=<프로젝트 API Key>
VITE_PUBLIC_POSTHOG_HOST=https://us.i.posthog.com
```

> 값이 비어 있으면 PostHog 초기화가 자동으로 스킵됩니다.

### 추적되는 주요 이벤트

| 이벤트 | 설명 |
|--------|------|
| `game_mode_selected` | 게임 모드 선택 |
| `game_started` | 게임 시작 |
| `game_completed` | 게임 정상 완료 |
| `game_over` | 게임 오버 |
| `game_abandoned` | 게임 중도 포기 |
| `tutorial_step_completed` | 튜토리얼 단계 완료 |
| `tutorial_skipped` | 튜토리얼 스킵 |
| `$pageview` | 페이지 이동 (자동 수집) |

## 8. Sentry — 프론트엔드 에러 추적 (선택)

### 용도
- JavaScript 에러 및 스택 트레이스 실시간 수집
- Web Vitals(LCP, INP, CLS) 모니터링
- React 렌더링 에러 경계(Error Boundary) 연동

### 가입 및 설정 방법

1. [Sentry](https://sentry.io) 회원가입 (무료 티어 사용 가능)
2. 프로젝트 생성 → Platform: **React** 선택
3. **Settings → Projects → <프로젝트> → Client Keys(DSN)** 에서 DSN 복사

### 환경 변수 설정 (`FE/.env`)

```
VITE_SENTRY_DSN=<발급받은 DSN>
```

> 값이 비어 있으면 Sentry 초기화가 자동으로 스킵됩니다.

## 9. Grafana Faro (Alloy) — 프론트엔드 로그 수집 (선택)

### 용도
- 프론트엔드 에러 로그를 Grafana Loki로 전송
- API 요청 ID(X-Request-Id)를 통한 FE-BE 로그 연계
- 자체 서버에 구축된 Grafana Alloy가 수신 엔드포인트 역할

### 설정 방법

Grafana Alloy는 자체 서버에서 운영되므로 별도 외부 가입 불필요합니다.  
`INFRA/docker-compose.monitoring.yml`로 Alloy 컨테이너를 실행하면 `http://<서버IP>:12347` 엔드포인트가 활성화됩니다.

### 환경 변수 설정 (`FE/.env`)

```
VITE_FARO_URL=https://agent-dev.lets-git-it.kr/collect   # 개발계 예시
```

> Nginx가 `agent.*.lets-git-it.kr` 도메인을 Alloy 컨테이너(12347 포트)로 프록시합니다.  
> 값이 비어 있으면 Faro 초기화가 자동으로 스킵됩니다.
